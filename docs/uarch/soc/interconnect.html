Interconnect and clocks¶

This page covers how requests move between the CPU, the host, memory and the peripherals: the AXI types and address constants, the main crossbar, the peripheral branch, and the clock domain.

Related notes: SoC, Peripherals and registers and Memory.

AXI types: rtl/common/soc_axi_pkg.sv¶

This package applies PULP’s typedef macros once, so every local module uses the same channel layout:

  • 32-bit byte addresses;

  • 32-bit data and four byte strobes;

  • 4-bit IDs at an endpoint;

  • one user bit; and

  • an ID-free AXI-Lite type for registers.

The crossbar has two initiator ports. It prepends one routing bit and produces a 5-bit ID on its target side. Those extra bits let the crossbar return a response to the initiator that issued the request. The package defines complete request and response structs, so a module port carries all five AXI channels without a long flat port list.

Address constants: rtl/common/soc_pkg.sv¶

This package defines the DDR window, DMA-region, UART, timer, SoC-CSR and host-console base addresses. Its addr_in_dma_buf function performs the half-open 16 KiB range check used by the memory target. The exact ranges are on the Memory page.

AXI interconnect¶

rtl/bus/axi_interconnect.sv binds two initiator request/response structs to one PULP axi_xbar:

Initiator index

Source

0

CPU uncached loads/stores and MMIO

1

host AXI

Target index

Decode

0

0x1fff_c000 <= address < 0x2000_0000 (the DMA region)

1

0x8000_0000 <= address <= 0xffff_ffff

Each side permits at most one transaction per port. FallThrough is disabled, atomic operations are disabled, and CUT_ALL_PORTS cuts every AXI channel, including the response and backpressure paths. There are no other configured pipeline stages. The cuts add registered AXI transfer latency and keep one-transfer-per-cycle throughput. They bound the fabric’s combinational timing and let PULP handle arbitration, ID extension, independent read and write channels, bursts and backpressure.

The memory target covers only the 16 KiB uncached DMA region at the top of the DDR window, so the crossbar itself decides what is legal. An AXI access to any other address below 0x8000_0000, including ordinary cached DDR, has no target and receives a decode error from the crossbar’s error slave.

Peripheral branch: rtl/bus/axi_peripheral_subsystem.sv¶

An axi_cut (a register slice on all five channels) sits between the main crossbar’s peripheral port and this branch. Without it, the crossbar’s spill registers and the AXI to AXI-Lite conversion were combinational through each other. It adds a cycle each way to every peripheral access.

The peripheral target has three layers:

  1. PULP axi_to_axi_lite removes IDs and converts the full-AXI request into AXI-Lite control transfers. It is configured for one read and one write transaction.

  2. A second axi_cut, on the AXI-Lite side. The conversion splits bursts into single transfers, and without this slice its state and the Lite crossbar’s page decode were combinational through each other.

  3. PULP axi_lite_xbar decodes one host port onto 4 KiB pages: UART, timer, SoC CSRs and the host console UART. The first page, at 0x8000_0000, has no target, and the Lite crossbar answers it with a decode error. The timer is also decoded at the CLINT offsets (0x8001_0000), which reach the same timer.

The Lite crossbar limits every port to one transaction, disables fall-through, uses CUT_ALL_PORTS, and has no default target enabled. Requests must therefore use one of the documented pages. Each peripheral still owns its local offset checking and response behavior.

In soc.sv, each UART also sits behind its own axi_cut. A register write reached the UART’s baud-rate counter through the Lite crossbar’s response logic in one cycle; the slice breaks that path. UART accesses only print or relay the console, so their extra cycle each way costs nothing a program notices.

All of these slices add latency to MMIO only. Cached loads and stores, instruction fetch and DDR traffic never pass through the peripheral branch.

Clock domain¶

The whole SoC runs on one clock, core_clk, so there are no internal clock crossings. CPU uncached AXI and the CPU line port are direct core-clocked connections.
