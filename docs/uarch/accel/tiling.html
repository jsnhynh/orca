FIN hardware tiling¶

FIN has a physical 16 by 16 systolic array, but software can submit matrices larger or smaller than 16. The tiled controller repeatedly uses that fixed array, accumulates partial results, and handles incomplete edge tiles. One start command covers the whole matrix multiplication.

Related notes: FIN accelerator, FIN systolic array, FIN datapath, FIN control FSM, and FIN AXI interfaces.

The matrix equation¶

FIN computes:

A[M by K] x B[K by N] = C[M by N]

M is the number of output rows, N is the number of output columns, and K is the length of each dot product. One output element is:

C[m,n] = A[m,0] * B[0,n]
       + A[m,1] * B[1,n]
       + ...
       + A[m,K-1] * B[K-1,n]

ORCA calls A the activation matrix and B the weight matrix. Both contain signed INT8 values. Accumulation uses signed 32-bit two’s-complement arithmetic. C is either kept as INT32 or post-processed into an INT8-range value stored in a 32-bit word.

The array can work on at most 16 rows, 16 columns, and 16 K elements at once. Hardware therefore divides the dimensions into tiles. m0, n0, and k0 are the first row, column, and K element of the current tile.

Loop order¶

The controller deliberately keeps a complete A row strip on chip. For one M tile, that strip contains up to 16 rows and all K elements. Every N tile then reuses it:

for each 16-row M tile
  load A[m0 : m0+16, 0 : K] once

  for each 16-column N tile
    clear the local C partial tile
    load this tile's bias values, when enabled

    for each 16-element K tile
      load B[k0 : k0+16, n0 : n0+16]
      select the matching 16-element group from the resident A strip
      preload B into the array
      compute and accumulate into the local C tile

    apply final post-processing
    store C[m0 : m0+16, n0 : n0+16]

This ordering is important. Loading A inside the N loop would fetch the same bytes once for every output-column tile. The current design fetches them once per output-row tile instead. It does not yet overlap DMA and compute.

On-chip storage¶

The activation capacity limits tiled jobs to K <= 1024. The activation scratchpad is physically banked and stores A transposed as A[k][row], because the systolic array consumes one K position across all active rows each cycle. The weight scratchpad keeps ordinary row-major B[k][column] data.

External memory layout¶

Software owns one permitted byte arena and packs the matrices inside it. FIN does not allocate memory. The job contains an arena base and size, a byte offset for each object, and a byte stride between rows.

For row-major data:

A[m,k] address = arena_base + a_offset + m * a_stride + k
B[k,n] address = arena_base + b_offset + k * b_stride + n
C[m,n] address = arena_base + c_offset + m * c_stride + n * 4
bias[n] address = arena_base + bias_offset + n * 4

Offsets do not have to be adjacent. A convenient packer may place a descriptor, A, B, bias, C, and scratch space one after another with alignment, but the hardware only depends on the submitted offsets and strides.

For a tile beginning at (m0, n0, k0), the controller forms:

A strip = arena_base + a_offset + m0 * a_stride
B tile  = arena_base + b_offset + k0 * b_stride + n0
bias     = arena_base + bias_offset + n0 * 4
C tile   = arena_base + c_offset + m0 * c_stride + n0 * 4

The A address has no k0 term because the whole K-wide strip was already loaded. act_group = k0 / 16 selects its current group locally.

Rectangle DMA¶

A tile cut from a larger row-major matrix is usually not contiguous. A 16 by 16 B tile may require sixteen short row transfers separated by b_stride. FIN’s DMA engine therefore accepts a rectangle rather than a simple byte count:

direction, local region, external address, external row stride,
row count, elements per row, local fill size, transpose flag

The engine handles one rectangle at a time. It breaks rows into AXI bursts of at most 16 words and never crosses a 4 KiB AXI boundary. A and B are byte elements; bias and C are 32-bit elements. Activation loads transpose the rectangle while writing the scratchpad, so they consume one local write cycle per byte.

The local fill dimensions are part of the command. On an edge tile, the DMA writes zero into unused activation or weight entries. The array can then run its normal 16 by 16 schedule without special arithmetic for invalid lanes.

Controller sequence¶

The tiled state path is:

IDLE -> LATCH -> VALIDATE -> LOAD_A
     -> SETUP_TILE -> [LOAD_BIAS] -> LOAD_B -> PRELOAD -> COMPUTE
     -> NEXT_K -- more K --> LOAD_B
               -- final K -> STORE -> NEXT_TILE
     -> more N --> SETUP_TILE
     -> more M --> LOAD_A
     -> DONE

LATCH snapshots every job CSR. Software may prepare the next job while FIN is busy without changing the active one. VALIDATE pipelines one shared multiplier over five steps: each A, B, or C span result is checked while the next product is launched. No DMA request is issued until every check passes.

PRELOAD and COMPUTE retain the original single-tile array timing. Tiling is an outer control loop, not a new stage inside the array.

Partial sums and post-processing¶

Each K tile produces only part of C. The first K tile starts a new local output; later K tiles add to the resident INT32 words. Bias, arithmetic right shift, saturation, and ReLU are applied only after the final K tile. An intermediate result never leaves through the output DMA.

The output memories have one read and one write port per column. The accumulation read is scheduled before the corresponding write, so one physical copy is sufficient; there is no output ping-pong buffer.

Raw mode remains available for debugging one physical 16 by 16 tile. Its acc_en bit keeps an intermediate INT32 partial for another software launch. Its raw_en bit returns the final INT32 result instead of applying post-processing. Tiled mode generates those decisions internally.

Edge tiles¶

Dimensions do not have to be multiples of 16. At each tile the controller calculates:

valid_m = min(16, M - m0)
valid_n = min(16, N - n0)
valid_k = min(16, K - k0)

Unused A and B lanes are zero-filled. Only valid_n bias words are loaded, and the store sends only valid_m rows of valid_n C elements. This keeps an odd shape such as 13 by 29 by 35 from reading past an input row or overwriting bytes beside an output row.

Job validation¶

Before issuing DMA traffic, hardware rejects:

  • zero dimensions or K > 1024;

  • unaligned arena, offsets, or strides;

  • row strides shorter than their logical rows;

  • 32-bit address overflow; and

  • any A, B, bias, or C span outside the declared arena.

The first error is recorded with a reason, field identifier, and the submitted run ID. A failed job issues no later requests and cannot report successful completion. The BSP repeats these checks in orca_fin_check() and additionally rejects unknown flag bits or a shift above 31 before submission. The hardware CSR fields only carry the defined flag and five-bit shift values, so those software-only checks are not hardware error cases.

The job-level arena check and the SoC DMA-region check solve different problems. FIN proves that a tensor stays inside the arena software described; the memory target independently proves that every DMA address stays inside the system’s uncached region. The current span checks do not reject two valid tensor spans that overlap each other.

Registers and counters¶

The tiled record occupies FIN offsets 0x720 through 0x758. Completion, error, and counter registers occupy 0x75c through 0x77c. The complete register table is in FIN accelerator; the source of truth is rtl/periph/peakrdl/fin/fin.rdl.

The counters separate time spent reading, computing, writing, and waiting on AXI. tile_ops counts physical 16 by 16 array operations. valid_macs counts only mathematically useful multiply-accumulates, so edge padding does not look like useful work.

Activation-strip reuse and packing four aligned activation bytes into each local SRAM write both cut the DMA-read cycles a tiled job spends, and the loop order above is what makes the reuse possible. The decision records hold the measured cycle counts.

fin_tiling_tb covers the complete 16/32/48 M/N/K matrix, K=80, odd edges, padded strides, randomized AXI stalls, invalid jobs, counters, repeated run IDs, and raw mode after tiled jobs. It also counts accepted A-load commands: there must be exactly one per M strip. A per-word allow set rejects any DMA access outside a declared tensor row.

Two verification habits are intentional. The size matrix catches counter-wrap bugs that one convenient square shape can hide. Fault injection proves that a passing assertion is sensitive: disabling accumulation breaks the numerical tests, widening edge reads breaks the allow-set check, and refetching A breaks the reuse counter gate.

Limits¶

  • DMA, array compute, and output stores are sequential; there is no prefetch overlap.

  • Only one DMA rectangle may be outstanding.

  • The A row strip limits K to 1024.

  • Aligned activation groups pack four bytes into one local SRAM write; unaligned data, tails, and zero fill remain byte-serial.

  • A and B are INT8; accumulation and raw C are INT32.

  • There is no sparse-data support, INT4 path, descriptor queue, or cache coherence.
