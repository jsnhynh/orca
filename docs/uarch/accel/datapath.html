FIN datapath¶

rtl/accel/fin_datapath.sv turns controller coordinates into vectors for the systolic array. It owns every FIN scratchpad, the array instance, output alignment, K-tile accumulation, and the connection to post-processing. rtl/accel/postproc.sv owns the final bias, shift, saturation, and ReLU pipeline.

Related notes: FIN accelerator, FIN systolic array, FIN control FSM, and FIN AXI interfaces.

Why the memories are banked¶

One physical compute cycle needs 16 weights or 16 activations in parallel. A single 32-bit RAM port supplies only four INT8 values. FIN therefore uses four 32-bit banks and treats each word as four byte lanes:

32-bit word = {byte lane 3, byte lane 2, byte lane 1, byte lane 0}
four banks x four lanes = sixteen INT8 values

The helper functions near the top of fin_datapath.sv implement this packing:

  • pack_byte_wdata(data, lane) places one byte into its 32-bit lane;

  • byte_lane_mask(lane) enables only that byte of the RAM write; and

  • unpack_byte(word, lane) selects one byte after a read.

BYTE_LANES=4, BYTE_BANKS=4, and each RAM uses an 8-bit write-mask granularity. The elaboration-time assertion requires ACT_STRIP_K to be a power of two at least as large as N, because the address slicing assumes that shape. It is 1024.

Activation banks use orca_sram_1rw_xpm, with block RAM in synthesis and a generic simulation adapter. The other scratchpads use orca_ram_1rw for one shared read/write port or orca_ram_1r1w for separate read and write ports. All provide synchronous reads: an address accepted in one cycle produces its data after the following clock edge. Activation byte masks and write-first behavior are preserved across the two implementations.

Weight scratchpad¶

The logical weight address is row-major:

logical index = K row * 16 + N column

For N=16, fin_datapath.sv divides that index as follows:

bits [7:4] = K row and physical RAM address
bits [3:2] = one of four RAM banks
bits [1:0] = one of four byte lanes in the 32-bit word

For example, B[2,13] has logical index 2*16+13 = 45. It is stored at RAM address 2, bank 3, lane 1. Reading row 2 enables all four banks at address 2, then the generated gen_weight_rd wiring unpacks columns 0 through 15 into the weight_row vector.

weight_wr.packed_word=1 replaces all four lanes of one bank in one cycle. The DMA uses this fast path for four aligned consecutive weight bytes. packed_word=0 selects one byte lane with the write mask; this is used for direct AXI-Lite byte stores and unaligned or edge DMA data.

When there is no write, sys_ctrl.weight_row selects the synchronous read address. sys_ctrl.preload enables that read. The first preload cycle primes the RAM; each following cycle asserts one weight_ld and copies the returned 16-byte row into one PE row.

Activation scratchpad¶

The activation storage is larger: 16 * 1024 = 16384 bytes. It holds up to 16 M rows across the complete K dimension so the controller can reuse A for every N tile.

External memory stores A in ordinary row-major order as A[m][k]. The array needs all 16 K positions for one M row at once. DMA therefore writes the local logical index in transposed order:

local index = K position * 16 + M-within-tile row

The index is physically divided into:

bank       = K bits [3:2]
byte lane  = K bits [1:0]
RAM address = {K bits [9:4], M-within-tile row [3:0]}

As a numerical example, local A[row=5][k=27] uses K group 1 because 27/16=1. Within that group K lane 11 selects bank 2, byte lane 3, and the RAM address is {group 1, row 5} = 21.

During compute, sys_ctrl.act_group selects which 16-wide K tile is active and sys_ctrl.act_col selects the M row flowing through the array. All four banks read {act_group, act_col}. The gen_act_rd wiring chooses bank r/4, lane r%4 for array K row r, producing all 16 A values at once.

Four consecutive K positions share one physical RAM word when K is aligned to four: the bank and address stay fixed while K bits [1:0] select its four byte lanes. act_wr_t.packed_word therefore writes all four lanes from one held AXI beat in one local cycle. The write address names the first logical activation. Unaligned external data, a K tail shorter than four, zero fill, and the non-transposed mode use the byte-lane mask and write one byte per cycle.

Bias scratchpad and lane registers¶

Bias has 16 signed 32-bit entries in one orca_ram_1rw. Post-processing needs all 16 biases in parallel, but they remain constant for a complete output tile. Instead of building 16 RAM read ports, preload copies them into the register array bias_vec one entry per cycle.

bias_load_idx_q encodes both the requested address and the one-cycle RAM latency:

preload cycle, index 0: request bias[0], capture nothing
preload cycle, index 1: request bias[1], capture returned bias[0]
...
preload cycle, index 15: request bias[15], capture returned bias[14]
preload cycle, index 16: no new read, capture returned bias[15]

Leaving preload resets the index to zero for the next tile but does not clear bias_vec. That is safe because all 16 entries are replaced during every preload, and bias_en=0 makes post-processing ignore them.

Synchronous reads into the array¶

weight_row[16] and act_col[16] are combinational byte selections from the registered RAM outputs. sys_arr consumes them on a clock edge.

The controller accounts for the RAM latency rather than adding ready/valid signals:

  • preload counter 0 requests weight row 0;

  • preload counter 1 loads PE row 0 and requests weight row 1;

  • the activation RAM repeatedly reads M row 0 during preload;

  • compute counter 0 consumes M row 0 while requesting row 1; and

  • later compute counters let the last wave drain after all 16 M rows entered.

The details of multiplication, skew, and propagation are in Systolic array.

Output deskew¶

The raw bottom outputs do not finish together. Each activation crosses two registers per PE column, so psum_out_raw[c] arrives 2*c cycles later than column 0. gen_deskew delays each lane by the complementary amount:

deskew delay for column c = 2 * (15 - c)

Column 0 receives 30 registers, column 1 receives 28, and column 15 is a direct connection. After deskew, all psum_out[c] values refer to the same C row in the same cycle.

Every deskew register clears on rst or whenever compute_en is low. While compute is active, the chain advances every clock. The controller’s valid window begins only after the complete array and deskew latency has passed.

K-tile accumulation¶

A K dimension greater than 16 produces several partial dot products. Output RAM holds the current 16 by 16 C partial tile. Before a valid new partial arrives, out_wr_ctrl.rd_en requests the corresponding old row. The separate read port returns it one cycle later as out_rd_data.

For every column:

out_partial_data = partial_accumulate ? out_rd_data : 0
psum_plus_acc     = psum_out + out_partial_data

The first K tile drives partial_accumulate=0, so stale RAM bits cannot leak into a new C tile. Later K tiles drive it high. The 32-bit addition wraps on overflow and occurs before optional post-processing.

There is one output memory, not a ping-pong pair, for each of the 16 columns. Each orca_ram_1r1w has an independent read and write port. The accumulation read precedes the matching raw write by one cycle and the matching processed write by four cycles, so the same storage safely supplies the old value and then accepts the replacement.

Output banking and external reads¶

A compute write stores a complete C row in one cycle: every column RAM uses the same row address and receives its own out_wr_data[c].

An AXI-Lite or DMA read sees the output as 256 linear words:

linear word index = row * 16 + column
selected RAM      = index[3:0]       (column)
RAM address       = index[7:4]       (row)

For example, local C[3,10] is word index 58. Its byte offset in FIN’s local window is 0x300 + 4*58 = 0x3e8; physically it is row address 3 in column RAM 10.

out_ext_read permits an external read only when the controller is neither requesting an accumulation read nor writing a compute result. Internal accumulation has read-port priority. out_ext_bank_q remembers the requested column across the synchronous RAM latency, then selects that column from the 16 returned words. Requests are not queued if software violates the rule and reads while compute owns the ports, so software waits for FIN to stop being busy.

Raw and processed write paths¶

out_wr_ctrl.raw_output selects what reaches each output RAM:

raw_output = 1: store psum_plus_acc as signed INT32
raw_output = 0: store sign-extended postproc INT8 result in a 32-bit word

Intermediate K tiles must use the raw path so precision is not lost before the next partial is added. On the final K tile, tiled raw_en chooses between returning INT32 and applying post-processing. Raw programming mode derives the same choice from its acc_en and raw_en controls; the exact raw-mode sequence is described in Control FSM.

Post-processing: postproc.sv¶

postproc is 16 lanes wide and has three registered stages. A three-bit valid_r shift register follows the data. Each data stage writes only when its matching valid bit is high, reducing unnecessary register toggles on bubbles.

stage 1: biased  = psum + (bias_en ? signed bias : 0)
stage 2: shifted = biased >>> shift
         sat     = clamp shifted to [-128, 127]
stage 3: result  = (relu_en and sat is negative) ? 0 : sat

The shift is arithmetic, so a negative value keeps its sign. Saturation uses 0x0000007f as the upper bound and 0xffffff80 as the lower bound. ReLU tests the sign bit of the already-saturated INT8 result. valid_out is produced by the module even though fin_datapath leaves it unconnected; the controller uses its matching fixed three-cycle write window instead.

Two numerical examples make the order visible:

psum=300, bias=-20, shift=1, ReLU on
stage 1: 280
stage 2: 140 -> saturates to 127
stage 3: 127 stays 127

psum=-40, bias=8, shift=2, ReLU on
stage 1: -32
stage 2: -8, already inside [-128,127]
stage 3: negative -> 0

With raw_output=1, both examples bypass all three stages and store the original accumulated 32-bit value. Bias, shift, and ReLU controls must remain stable for the output pass; they are shared by all lanes and are not carried with each pipeline entry.

Reset and limits¶

Reset clears control-facing registers, bias lane registers, deskew registers, and post-processing registers. The inferred RAM arrays are not cleared by reset. Correctness instead comes from DMA filling input regions, first-K accumulation gating stale output data, and valid windows ignoring warm-up.

The limits come from the structure:

  • activation storage supports K up to 1024;

  • aligned transposed activation groups write four bytes per local cycle, with byte writes for unaligned data, tails, zero fill, and raw mode;

  • only one 16 by 16 C tile is resident;

  • loads, compute, and stores do not overlap;

  • post-processing controls apply to a whole output tile; and

  • there is no rounding mode, wider accumulator, floating-point, or sparse execution path.
