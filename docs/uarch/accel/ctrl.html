FIN control FSM¶

rtl/accel/fin_ctrl.sv is the sequencer for the accelerator. It does not contain tensor data. It remembers the active job, checks whether its addresses are safe, walks the M/N/K tiles, tells DMA which rectangle to move, and generates cycle-exact enables for the datapath.

The state type and every control structure live in rtl/accel/fin_pkg.sv. Related notes: FIN accelerator, FIN hardware tiling, FIN AXI interfaces, FIN datapath, and FIN systolic array.

The important state is grouped by purpose:

job_m_last_q, job_k_last_q

m0_q, n0_q, k0_q

a_row_q, c_row_q, b_k_q

mul_p_q, mul_limit_q, mul_base_oob_q

legacy_partial_valid_q

err_*_q, done_id_q

ctr_q

sticky successful-completion bit

irq_pending_q

Active-high rst and ctrl.soft_rst return the controller to T_IDLE and clear all of these controller registers. They do not erase scratchpad RAM.

Start and job snapshot¶

The generated CSR block turns writing ctrl.start=1 into a registered single-cycle pulse. In T_IDLE, seeing that pulse moves the controller to T_LATCH. The extra latch state is required because the other fields written with start become visible after the same register-file edge. job_latch is high while the state is T_LATCH, so the following edge captures a stable record into job_q and mode_q.

START is accepted in T_IDLE or successful T_DONE; a pulse in other states is not queued. However, every START pulse clears sticky DONE and IRQ, including an unaccepted busy-state pulse. Software must check busy and retain exclusive ownership while describing and launching a job.

The registered START pulse adds one CSR-to-launch edge compared with the former write-modification strobe; compute and DMA pipeline latency are unchanged. Soft reset has priority over completion and clears the interrupt. It resets controller state but does not abandon accepted AXI DMA traffic: an outstanding rectangle drains normally and may continue writing external memory. Software must not reuse that memory until traffic is quiescent; no new DMA-idle CSR is provided by this change.

Tiled mode copies job_csr as one fin_job_t. Later CSR writes do not change the running job. Raw mode creates an equivalent internal record:

M=N=K=16
shift, bias_en, relu_en = raw control registers
internal raw-output request = ctrl.acc_en OR ctrl.raw_en

Representing both interfaces as job_q lets the same preload, compute, and store logic serve both modes.

Raw mode’s four DMA address registers are not part of that snapshot. The controller reads them when forming each rectangle command. Keep them unchanged until the raw job finishes; do not interpret the tiled snapshot guarantee as permission to reprogram a raw job’s later transfers.

State machine¶

The encoded states are all declared in fin_pkg.sv. The tiled path is:

T_IDLE -> T_LATCH -> T_VALIDATE -> T_LOAD_A
       -> T_SETUP_TILE -> optional T_LOAD_BIAS -> T_LOAD_B
       -> T_PRELOAD -> T_COMPUTE -> T_NEXT_K
          more K: --------------------^ through T_LOAD_B
          final K: -> T_STORE -> T_NEXT_TILE
       -> more N: T_SETUP_TILE
       -> more M: T_LOAD_A
       -> T_DONE -> T_IDLE

any validation or AXI error -> T_ERROR -> T_IDLE

Each state has one concrete responsibility:

State

Work and exit condition

T_IDLE

wait for start; sticky completion remains readable

T_LATCH

snapshot mode and all job fields; always advance

T_VALIDATE

run validation steps 0 through 4; raw mode skips the checks

T_LOAD_A

issue one activation-strip rectangle and wait for DMA response

T_SETUP_TILE

begin one (m0,n0) C tile; route to bias or B load

T_LOAD_BIAS

load the current N slice when needed and wait for DMA

T_LOAD_B

load the current (k0,n0) weight tile and wait for DMA

T_PRELOAD

prime synchronous RAM reads and load 16 PE weight rows

T_COMPUTE

feed A rows, drain the array, accumulate, and write local C

T_NEXT_K

count this physical operation; advance K or select store

T_STORE

DMA the valid part of the local C tile to external memory

T_NEXT_TILE

restart K and advance N first, then M, or finish

T_DONE

finish successful status; accept an immediate new start or return idle; IRQ remains latched

T_ERROR

finish error status, then return idle; IRQ remains latched

The state remains in each DMA phase until dma_busy_q && dma_rsp_valid makes dma_done true. dma_cmd_valid is high in a DMA state only while no command is outstanding. A cmd_valid && cmd_ready handshake sets dma_busy_q; the DMA response clears it. This prevents repeated commands while a slow transfer is still running.

Raw-mode state order¶

Raw mode has no A-strip reuse or validation record. Its route is:

IDLE -> LATCH -> VALIDATE -> SETUP_TILE -> LOAD_BIAS
     -> LOAD_A -> LOAD_B -> PRELOAD -> COMPUTE
     -> NEXT_K -> STORE -> NEXT_TILE -> DONE

VALIDATE exits immediately because mode_q=0. Raw mode always loads bias, even when raw output will bypass it, to preserve the externally visible transfer sequence of the original interface.

Tile loop and incremental addresses¶

m0_q, n0_q, and k0_q are element offsets, not tile numbers. Remaining elements and valid edge sizes are purely subtract-and-compare operations:

valid_m = min(16, M - m0)
valid_n = min(16, N - n0)
valid_k = min(16, K - k0)

The controller avoids a multiplier in the active tile loop by maintaining three row offsets:

a_row_q = a_offset + m0 * a_stride
c_row_q = c_offset + m0 * c_stride
b_k_q   = b_offset + k0 * b_stride

Advancing K by 16 adds b_stride << 4 to b_k_q. Advancing M by 16 adds a_stride << 4 and c_stride << 4 to their row bases. Advancing N only adds n0 when a command address is formed. At every new C tile, K returns to zero and b_k_q returns to b_offset.

The external command addresses are:

A strip = arena_base + a_row_q
B tile  = arena_base + b_k_q + n0
bias     = arena_base + bias_offset + 4*n0
C tile   = arena_base + c_row_q + 4*n0

A omits k0 because the complete K-wide strip is already resident. B is INT8, so n0 is a byte count. Bias and C are INT32, so their N offsets are multiplied by four.

Example tile walk¶

For M=20, N=33, K=24, the tile positions are:

m0 = 0, 16
n0 = 0, 16, 32
k0 = 0, 16

That produces 2 A-strip loads, 6 output stores, and 12 physical array operations. At the final corner, valid_m=4, valid_n=1, and valid_k=8. The DMA zero-fills all other local lanes, while the counter adds only 4*1*8=32 useful MACs for that physical operation.

DMA command generation¶

The active DMA state selects all fields of one fin_dma_cmd_t:

State

Region

Shape and special behavior

T_LOAD_A

activation

tiled: valid_m rows by full job K, stride a_stride, transpose locally, fill 16 rows by K; raw: 16 by 16

T_LOAD_B

weight

valid_k by valid_n, stride b_stride, fill full 16 by 16 tile

T_LOAD_BIAS

bias

one row of valid_n words, fill all 16 words

T_STORE

output

valid_m by valid_n words, stride c_stride, no fill

Raw mode substitutes the four raw DMA address registers and fixed tight strides. In tiled mode, bias is loaded only when bias_en=1 and raw_en=0. A raw INT32 result does not consume bias. fin_dma converts these rectangle commands into AXI activity as described in AXI interfaces.

Multi-cycle job validation¶

Validation is tiled-mode hardware enforcement before the first DMA request. One shared, output-registered 16 by 32 product computes long row spans over five steps. Two parallel 16 by 16 DSP partial products multiply the stride’s low and high halves. A fabric addition forms the upper 32 product bits; the low 16 bits come directly from the low partial product. DSP/fabric attributes express the mapping intent; the routed netlist must confirm it. The existing 48-bit product register is unchanged. A product is checked on the following step while the next product is launched. The bias-only check launches C, so valid jobs still use five validation steps.

vstep_q

1

none

B span

A result

3

B result, then bias span when bias is enabled

4

The multiplier keeps the complete 48-bit product and base additions keep a 33rd carry bit. Any high product or base bit fails before the remaining 32-bit arena-space comparison, so arithmetic cannot silently wrap:

fin_ctrl_tb’s span-product scenario checks the actual product against a full-width multiply and verifies its existing capture edge across 768 programmed jobs, including high products. The rewrite changes neither error priority nor validation latency. Physical timing improvement remains a separate implementation gate.

A span    = a_offset    + (M-1)*a_stride + K
B span    = b_offset    + (K-1)*b_stride + N
bias span = bias_offset + 4*N
C span    = c_offset    + (M-1)*c_stride + 4*N

Minimum legal strides are K bytes for A, N bytes for B, and 4*N bytes for C. Arena base, arena size, all offsets, and all strides are required to be four-byte aligned, except bias_offset is checked only when bias is enabled.

The validation reasons the controller emits are ZERO_DIM, CAPACITY, ALIGN, STRIDE, OVERFLOW, and ARENA. MODE and the flags field identifiers are defined in fin_pkg.sv but no current fin_ctrl branch emits them. Shift values are five bits by construction and are not otherwise rejected. The controller checks that each object fits in the declared arena; it does not check whether two legal object spans overlap.

Preload and compute cycle counter¶

counter is wide enough for 6*N values. It increments only in T_PRELOAD or T_COMPUTE and clears when those phases begin or end. A single counter is reused because no two phases overlap.

For N=16, the constants are:

PRELOAD_LAST   = 16
COMPUTE_LAST   = 72
FIRST_VALID_IN = 47
LAST_VALID_IN  = 62
FIRST_WRITE    = 50
LAST_WRITE     = 65

Preload outputs¶

sys_ctrl.weight_row=counter while the counter is below 16. Because the RAM is synchronous, counter 0 primes weight row 0 and counter i+1 pulses weight_ld[i]. sys_ctrl.preload also makes the PEs clear their arithmetic pipelines and causes bias to load one word per cycle.

Compute outputs¶

The activation RAM is primed with local M row 0 during preload. At compute counter 0, the array consumes row 0 while sys_ctrl.act_col requests row 1. It requests rows 1 through 15, then returns the address to zero while the wavefront drains. sys_ctrl.act_group=k0/16 selects the correct resident K group.

The deskewed sums for C rows 0 through 15 are valid during counters 47 through 62. pp_ctrl.valid_in marks those 16 clocks. A processed result is written three cycles later, counters 50 through 65. A raw result skips post-processing and uses the original 47 through 62 window.

When an old K partial is needed, out_wr_ctrl.rd_en runs one cycle before the 47-through-62 valid window. Its row address is the valid row number. This places synchronous output-RAM data at the accumulator before psum_out arrives.

Partial sums and raw output¶

For tiled mode:

partial_accumulate = k0 is not zero
raw_output = another K tile remains OR job.raw_en

Thus every intermediate K tile stores a full INT32 partial. The first K tile ignores old output RAM. The final K tile either applies post-processing or, when raw_en=1, stores the final INT32 sum.

Raw-mode partial history¶

Raw mode uses legacy_partial_valid_q across software launches:

  1. a launch with acc_en=1 stores an unprocessed INT32 tile;

  2. after compute, legacy_partial_valid_q becomes one;

  3. the next raw launch adds that resident tile before writing; and

  4. a launch with acc_en=0 clears the remembered-valid state after compute.

ctrl.raw_en=1 selects raw output for the current launch but does not keep the partial-valid state by itself. If neither acc_en nor raw_en is set, the current result uses post-processing. This history is controller state; the output RAM itself has no valid bits.

Completion, errors, and counters¶

The first error is sticky until the next job_latch or reset. Validation records vreason and vfield. A failed DMA load records AXI_READ plus A, B, or bias; a failed store records AXI_WRITE plus C. Both errors and normal completion copy job_q.run_id to done_id_q. No later error overwrites the first one.

The visible signals have precise timing:

status.busy = state is neither T_IDLE nor T_DONE
status.done = sticky done_r
status.err_pending = sticky err_valid_q
irq = sticky irq_pending_q

Consequently busy is low during successful T_DONE, while irq is high. At the edge leaving T_DONE, done_r becomes one and remains visible in T_IDLE. A start has priority over setting done_r: an immediate restart from T_DONE clears done rather than briefly reporting the previous job. T_ERROR counts as busy for its one state cycle, then returns idle. An error does not set status.done. Entering T_DONE or T_ERROR sets IRQ unless reset, soft reset, or START has priority. IRQ remains asserted after returning idle, until reset, soft reset, or another START; it is not a one-cycle pulse. This is what permits the core-domain two-flop synchronizer to observe completion.

All counters clear at job_latch:

  • dma_read_cycles increments in T_LOAD_A, T_LOAD_B, or T_LOAD_BIAS;

  • compute_cycles increments in both T_PRELOAD and T_COMPUTE;

  • dma_write_cycles increments in T_STORE;

  • stall_cycles increments when DMA needs an AXI handshake that does not advance;

  • tile_ops increments once in every T_NEXT_K; and

  • valid_macs adds valid_m * valid_n * valid_k at the same point.

Phase counters include command setup and response-wait cycles because they count whole controller states. stall_cycles is a subset focused only on blocked AXI channels, not every cycle in a DMA state.

Limits¶

  • soft_rst resets the controller, not the DMA transaction engine. Accepted DMA work drains independently and may still write memory; there is no software-visible DMA-idle acknowledgement for safely restarting that arena.

  • Validation protects tiled jobs. Raw addresses are used as supplied.

  • One rectangle can be outstanding, so no DMA phase overlaps another phase.

  • Preload and compute windows are constants derived for the current array and memory latency. Changing N or a pipeline latency requires re-derivation.

  • The controller relies on fixed-latency local RAM; it has no per-vector ready/valid backpressure inside the datapath.
