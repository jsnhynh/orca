FIN AXI interfaces¶

FIN has two independent bus roles:

  • an AXI4-Lite target receives software register and scratchpad accesses;

  • a full AXI4 initiator performs DMA between main memory and FIN.

AXI-Lite is appropriate for isolated 32-bit control accesses. Full AXI can transfer bursts, so it is appropriate for matrices. rtl/accel/fin.sv joins the two roles to the controller and datapath.

Related notes: FIN accelerator, FIN control FSM, FIN datapath, FIN hardware tiling, and SoC.

Top-level routing in fin.sv¶

The top first creates core-side versions of both AXI interfaces. In a normal single-clock build they are direct assignments. With ORCA_FIN_MULTI_CLOCK, soc_axi_lite_cdc_bridge moves the target interface from fabric_clk into FIN’s clk, while soc_axi_cdc_bridge moves the DMA initiator from FIN’s clock back to fabric_clk. Parameters CDC_LOG_DEPTH and CDC_SYNC_STAGES select the bridge queue depth and synchronizer depth.

Everything below these bridges runs on FIN’s active-high rst. The PULP AXI demux uses an active-low reset, so fin.sv connects rst_ni = !rst.

AXI-Lite address split¶

An axi_lite_demux has two outputs and permits at most one transaction. It examines local address bits [11:8] independently for write-address and read-address channels:

0x700-0x7ff -> output 1 -> fin_csrs
all others  -> output 0 -> sram_window

FallThrough=0 and every spill option is zero, so the demux supplies its own transaction tracking without extra spill registers on individual channels.

Shared scratchpad ports¶

The direct target and DMA both reach the same datapath ports. fin.sv uses small priority muxes rather than queues:

weight write: AXI-Lite if slv_weight_wr.we, otherwise DMA
activation write: AXI-Lite if slv_act_wr.we, otherwise DMA
bias write: AXI-Lite if slv_bias_wr.we, otherwise DMA
output read: DMA if mst_out_sram_re, otherwise AXI-Lite

The output read enable is the OR of both request enables, and the DMA address wins when both are high. A losing request is not remembered. The software contract therefore forbids direct scratchpad access while a job is busy.

CSR target: fin_csrs.sv¶

fin_csrs contains no register state of its own. It maps ORCA’s structured AXI-Lite channels to the scalar ports of generated fin_regs, then maps the generated hwif_in and hwif_out structures to FIN types.

The generated block needs seven local address bits because its last register is at offset 0x7c inside the 0x700 CSR page. The wrapper passes axi_req.*.addr[6:0]. The full register table is in FIN accelerator.

The mapping has three directions:

  • raw control, DMA source addresses, mode, and tiled job fields flow from hwif_out to ctrl_reg, mode, and fin_job_t;

  • status, completion, errors, and counters flow from FIN into hwif_in; and

  • the generated AXI logic owns all ready/valid response behavior.

ctrl_reg.start uses the value of the RDL singlepulse field. Only writing START=1 emits a one-cycle request; reset or flag-only writes do not launch work. soft_rst and the other raw controls use their stored value. The controller waits through T_LATCH before sampling the complete register record; see Control FSM.

Scratchpad window reads and writes while the controller or DMA is busy return SLVERR without accessing local SRAM. Responses retain that error under backpressure. This also protects an outstanding DMA rectangle after soft reset.

Direct scratchpad target: sram_window.sv¶

AXI writes have independent address (AW) and data (W) channels. They may arrive in either order. aw_have_q and w_have_q remember which half has arrived, while write_offset_q, write_data_q, and write_strb_q preserve the payload. write_present blocks a read from being accepted after either half of a write has appeared.

The five-state machine is:

S_ACCEPT -- AW and W collected --> S_WRITE_EXEC --> S_WRITE_RESP
    |
    +---- AR accepted ----------> S_READ_WAIT  --> S_READ_RESP

State behavior is:

State

Behavior

S_ACCEPT

assert aw_ready and/or w_ready for missing write halves; allow ar_ready only when no write is present

S_WRITE_EXEC

pulse one decoded scratchpad write when the address is supported

S_WRITE_RESP

hold b_valid and its response until b_ready

S_READ_WAIT

wait one cycle for synchronous output RAM and capture out_sram_rdata

S_READ_RESP

hold r_valid, data, and response until r_ready

Only one transaction is active. Response backpressure is safe because the registered payload remains unchanged until the matching handshake.

Direct write decode¶

All offsets below 0x240 are writable and map to three adjacent ranges:

0x000-0x0ff: weight byte, waddr = offset
0x100-0x1ff: activation byte, waddr = offset - 0x100
0x200-0x23f: bias word, waddr = (offset - 0x200) / 4

Weight and activation writes pick one byte from the 32-bit AXI beat according to the one-hot strobe: 0010 selects bits 15:8, 0100 selects 23:16, 1000 selects 31:24, and every other strobe pattern selects bits 7:0. The selected byte is sent with a byte-addressed local index. Software should issue ordinary single-byte strobes; multiple or zero strobes do not write several bytes.

Bias writes use all 32 data bits and ignore byte strobes inside this wrapper. Software therefore writes a complete aligned word.

Unsupported writes still complete but return AXI SLVERR; they do not pulse a scratchpad write enable.

Direct output read¶

Only offsets 0x300-0x6ff are readable. On the AR handshake, out_sram_re pulses and the word address is (offset-0x300)/4. S_READ_WAIT captures the synchronous RAM result on the following cycle. An unsupported read returns zero with SLVERR. Output RAM is not writable through this target, and input scratchpads are not readable through it.

Rectangle commands into fin_dma.sv¶

The controller and DMA use a command/response handshake simpler than AXI:

command accepted = cmd_valid && cmd_ready
completion       = one-cycle rsp_valid with rsp_err

cmd_ready is high only in D_IDLE. A command is copied into cmd_q when accepted and remains stable internally until completion. There is no response ready input; rsp_valid is a one-cycle notification in D_RSP.

One fin_dma_cmd_t describes a two-dimensional rectangle:

Field

Meaning

store

0 loads external memory into FIN; 1 stores FIN output

region

weight, activation, bias, or output scratchpad

local_transpose

use local elem*16+row instead of row*16+elem

ext_addr

byte address of row 0, element 0

ext_stride

external bytes between adjacent rows

rows, elems

valid external rectangle

fill_rows, fill_elems

complete local region that a load must define, including zeros

Weight and activation elements are one byte. Bias and output elements are four bytes. word_region selects the size, and row_bytes computes the valid external byte span of one row.

DMA load state machine¶

The load path is:

D_IDLE -> D_LD_ROW -> D_LD_AR -> D_LD_R -> D_LD_WR
                         ^          ^           |
                         |          +-----------+ next beat in burst
                         +----------------------+ next burst
       -> next D_LD_ROW or D_RSP -> D_IDLE

The registers row_q and elem_q identify the local element. row_base_q holds the external start of the current row. elem_addr_q is the external address of the current element. word_addr_q is the next aligned AXI word to request, and row_last_word_q prevents a burst from reading into the next logical row.

The states work as follows:

State

Work

D_LD_ROW

calculate the aligned word containing the row’s last valid byte; select AXI read or a zero-only row

D_LD_AR

hold one AXI read address until accepted and record the burst beat count

D_LD_R

accept one 32-bit R beat into beat_q, remember its word index, and record a non-OKAY response

D_LD_WR

consume one byte or packed weight word from the held beat, or write zero for padding

D_RSP

pulse completion with the accumulated error bit

beat_hit checks that the held 32-bit word contains elem_addr_q. If more elements remain in the same word, D_LD_WR can consume them without another AXI beat. When the word is exhausted, the FSM returns to D_LD_R if its burst still has beats or D_LD_AR for a new burst.

For a memory-backed element, ld_byte selects the correct byte using address bits [1:0]. For an element outside rows x elems but inside fill_rows x fill_elems, it writes zero without advancing the external address. At the end of a row, all external pointers rebase to row_base_q + ext_stride and local element returns to zero.

Local load addressing¶

Normal regions use:

local_idx = row_q * 16 + elem_q

Transposed activation commands use:

local_idx = elem_q * 16 + row_q

The region selects one local write structure. Output is store-only. Bias uses the complete held 32-bit word.

Aligned INT8 loads have a four-byte fast path, ld_word4. It is active for a normal weight load or a transposed activation load when four valid elements remain and both the external address and element index are word-aligned. One local write consumes the held AXI beat and advances four elements. For an activation, those four consecutive K positions are the four byte lanes of one physical scratchpad word. Raw activations, edges, zero fill, and unaligned loads fall back to one byte at a time. This changes local write throughput; it does not issue a wider AXI transfer.

AXI burst formation¶

Every AXI transfer is a 32-bit incrementing burst with DMA ID 1. choose_burst_beats takes the smaller of:

  • words remaining in the current row;

  • MAX_BURST_BEATS, which is 16; and

  • words remaining before the next 4 KiB address boundary.

The AXI length field is beats minus one. No burst crosses 4 KiB, and a row is never merged with the next row even if their addresses happen to be adjacent. The elaboration assertion limits MAX_BURST_BEATS to the legal AXI range 1 through 256.

The load side requests aligned 32-bit words even for byte tensors. An unaligned first byte is selected from its containing word, and the last burst stops at the word containing the row’s last valid byte.

DMA store state machine¶

Only the output region is stored. Output elements are 32-bit words, so there is no byte packing. The path is:

D_ST_ROW -> D_ST_AW -> D_ST_RD -> D_ST_W
                         ^           |
                         +-----------+ next beat in burst
                    -> D_ST_B -> next burst/row or D_RSP

D_ST_AW submits a burst address and saves its length. For each beat, D_ST_RD pulses the synchronous output-SRAM read and D_ST_W presents the returned word until the AXI W handshake occurs. These states alternate because the current design has one registered local read result rather than a FIFO. w.last is high on the final saved beat.

After all beats in a burst, D_ST_B waits for the AXI write response. If the row has more elements it creates another burst; otherwise it advances row_base_q by the external stride and starts the next row. A zero-element store goes directly to D_RSP.

AXI errors, stalls, and debug names¶

Any non-OKAY R response sets sticky err_q; any non-OKAY B response does the same. The DMA finishes the current rectangle, then reports rsp_err=err_q in D_RSP. fin_ctrl turns that into an A/B/bias read error or C write error.

axi_stall is high only when DMA is in a bus handshake state and the other side is not ready or valid:

AR waiting for ar_ready
R waiting for r_valid
AW waiting for aw_ready
W waiting for w_ready
B waiting for b_valid

Local zero-fill and SRAM-read cycles are work but are not AXI stalls. fin_ctrl adds axi_stall to the job’s stall_cycles counter.

state, next, rd_elems, wr_elems, dma_rd_done, and dma_wr_done are combinational aliases retained for waveforms and testbench hierarchy. The real registered FSM names are state_q and state_d.

Limits¶

  • One rectangle and one AXI burst may be outstanding.

  • Loads and stores never overlap each other or compute.

  • Aligned transposed activations consume one local write cycle per four bytes; unaligned data, tails, zero fill, and raw mode consume one cycle per byte.

  • Output stores alternate a synchronous SRAM read and an AXI W beat; there is no output FIFO.

  • Read errors are accumulated through the rectangle rather than aborting on the first bad beat.

  • Direct AXI-Lite scratchpad access is single-transaction and must not race an active DMA job.
