Stage 2: Decode¶

Decode is the simplest stage. Two instruction words go in and two instruction_t structs come out, into one register (the decode register) that rename reads in the next cycle. There are no queues, no arbitration and no recovery state.

Decode is also where the core decides what is legal. Every illegal-instruction trap in ORCA starts here, so this small file carries a large share of the architectural contract.

Related notes: Stage 1: Fetch, Stage 3: Rename, ISA and software contract, Machine-mode traps.

Files¶

File

Job

rtl/cpu/2-decode/decode.sv

full decode and legality checks into the decode register

rtl/cpu/common/uarch_pkg.sv

instruction_t, CSR ID encoding

rtl/common/riscv_isa_pkg.sv

opcodes, funct fields, CSR addresses, causes

Packets and constants¶

riscv_isa_pkg.sv describes the software-visible language: 32-bit addresses, instructions and data, the 32 integer registers, reset PC zero, instruction encodings, CSR addresses, and exception causes. uarch_pkg.sv describes the machine that implements it: two-wide fetch/dispatch, a 64-entry ROB, queue sizes, six execute slots, and the packed records exchanged between stages.

Keeping those roles separate matters. Changing an opcode constant changes the ISA contract. Changing SCHED_ENTRIES changes only capacity and should not change what software observes. The compact CSRID_* values are likewise an internal encoding; software still uses the architectural 12-bit CSR address.

The decoded packet¶

Everything downstream travels as one instruction_t. The unusual part is that it carries two operand pairs:

Field

Meaning

src_0_a, src_0_b

the ALU/AGU operand pair

src_1_a, src_1_b

the raw rs1 / rs2 pair

uop_0

primary funct3 (ALU op, load/store width, CSR op)

uop_1

branch condition funct3

For an ALU instruction, src_0 is what gets computed, possibly a PC and an immediate. For a branch, src_0 computes pc + imm (the target) while src_1 carries rs1 and rs2 for the condition compare. That is how one ALU produces both the branch target and the taken bit in one pass, and it is why execute can pack the whole branch resolution into one result word.

Stores use src_0_a/src_0_b for the address computation and src_1_b for the store data.

Each source_t is {data, tag, is_renamed}. Decode fills in data for immediates and the PC, and puts the architectural register number into tag. Rename later overwrites tag with a ROB tag.

Immediates¶

gen_imm is a casez over the opcode that produces the I, S, B, U and J forms. The sign extension is written out for each format.

CSR compression¶

A 12-bit CSR address is wide for a pipeline that implements only about twenty registers. Decode compresses it to a 5-bit csr_id:

CSRID_INVALID, CSRID_CYCLE, CSRID_MSTATUS, CSRID_MTVEC, ...
CSRID_SYS_ECALL, CSRID_SYS_EBREAK, CSRID_SYS_MRET, CSRID_SYS_WFI

System instructions (funct3 == 0) and CSR instructions share the opcode, so both decode into the same field. CSRID_INVALID marks a CSR that is not implemented, and it drives the illegal-instruction trap for an unknown CSR.

Counter aliases collapse: CSR_CYCLE and CSR_MCYCLE both become CSRID_CYCLE. The core has one physical counter, and the unprivileged alias is another name for it.

Legality¶

legal_inst is computed per opcode. The checks that matter:

Opcode

Rule

JALR

funct3 == 0

BRANCH

funct3 not in the two reserved encodings

LOAD

funct3 excludes 0b011, 0b110, 0b111

STORE

funct3 in {B, H, W}

ARI_ITYPE

shift-immediate funct7 must be 0 or 0x20

ARI_RTYPE

funct7 in {0, MULDIV, 0x20}, and 0x20 only for ADD/SRL

MISC_MEM

funct3 in {FENCE, FENCE.I}

AMO

funct3 == W, a known funct5, and rs2 == 0 for LR.W

SYSTEM

known funct12, and rd == 0 && rs1 == 0

CSR*

known csr_id, and no write to a read-only (addr[11:10] == 2'b11) CSR

That last rule is the architectural read-only-address check: a CSR instruction with write intent targeting an address whose top two bits are 11 is illegal. Write intent means CSRRW/CSRRWI, or a set/clear form with a non-zero source. WARL is a separate rule: a writable CSR may accept a write but force unsupported field values to a legal value in the CSR bank.

Decode also chooses the later execution path. Loads and stores carry their width/sign funct3; M-extension operations preserve funct7; branches carry their comparison in uop_1; fences carry their funct3; and CSR instructions carry both compact ID and CSR operation. Atomics carry funct3 (always W) and keep funct7, whose upper five bits are the atomic operation; aq/rl ride along unused. x0 may appear as a source, but destination write intent is suppressed wherever the architecture says there is no result.

Exceptions¶

Three exception sources leave this stage, all encoded into the same fields:

d_inst.exception = val && (!legal_inst || ecall || ebreak);
d_inst.exception_cause = ecall  ? CAUSE_MACHINE_ECALL
                       : ebreak ? CAUSE_BREAKPOINT
                       :          CAUSE_ILLEGAL_INSTRUCTION;
d_inst.exception_tval = legal_inst ? 32'd0 : inst;

mtval for an illegal instruction is the instruction word itself, as the specification asks and as the test handlers check.

An excepting instruction has has_rd and rd forced to zero. It still gets a ROB entry, because traps are precise and taken in order at commit, but it is never routed to an issue queue and never writes a register.

Handshake and the decode register¶

assign decode_rdy = rename_rdy || decode_empty;

always_ff @(posedge clk)
    if (rst || flush)    decoded_insts[i] <= '0;
    else if (decode_rdy) decoded_insts[i] <= (fetch_vals != '0) ? decoded_insts_next[i] : '0;

The instruction buffer’s head is decoded into decoded_insts, a register between decode and rename; rename, ROB allocation and queue insertion work from it in the next cycle. The register takes a new group when rename accepts the current one or when it holds nothing, so a bubble never blocks the buffer, and it holds its group while rename stalls. The buffer pops on the same decode_rdy edge. An empty fetch group loads zeros.

Reset and flush clear the register. flush is the union flush, which includes execute-time branch recovery. Anything in decode when a branch mispredicts is younger than that branch, so nothing needs to be preserved selectively. Decode has no error response or retry protocol: legal instructions advance, while illegal ones advance as ready exception-marked ROB work.

The register keeps the buffer, decode, rename and scheduler-entry path from chaining into one very long combinational path.

Known limits¶

  • No compressed (C) instruction support; every instruction is 32 bits and lanes are fixed to the 8-byte group.

  • No fusion or macro-op cracking.

  • WFI decodes to a valid system op but retires as a no-op; there is no low-power state.

  • FENCE and FENCE.I share the MISC_MEM opcode and are distinguished by uop_0 all the way through to commit.

Tests¶

sim/cpu/tb/2-decode/decode_tb.sv covers immediate generation, operand routing, CSR ID mapping, the legality matrix, and the register’s stall and flush behavior.
