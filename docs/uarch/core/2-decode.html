Stage 2: Decode¶

Decode converts two 32-bit words into two decoded instructions and holds them in one register that rename reads on the next cycle. It has no queues, arbitration or recovery state, and it decides legality, so every illegal-instruction trap starts here. A flush clears the register, since any instruction in decode during a mispredict is younger than the branch.

The RTL is rtl/cpu/2-decode/decode.sv. ISA constants (opcodes, CSR addresses, causes) live in rtl/common/riscv_isa_pkg.sv, and machine sizes and packed records live in rtl/cpu/common/uarch_pkg.sv. An opcode constant belongs to the ISA contract; a scheduler size changes only capacity.

Decoded Instruction¶

Each decoded instruction carries two operand pairs:

Field

Meaning

src_0_a, src_0_b

the ALU or AGU computation operands

src_1_a, src_1_b

raw rs1 and rs2

uop_0

main funct3 (ALU op, load/store width, CSR op)

uop_1

branch condition funct3

An ALU op computes on src_0, which may hold a PC and an immediate. A branch computes its target (pc + imm) on src_0 while src_1 carries rs1 and rs2 for the compare, so one ALU pass produces the target and the taken bit, and execute packs the resolution into one result word. Stores use src_0 for the address and src_1_b for the data.

Each source holds data, a tag and a renamed bit. Decode fills data for immediates and the PC and writes the architectural register number into the tag; rename replaces it with a physical register ID.

CSR IDs¶

Decode compresses the 12-bit CSR address into a 5-bit ID for the roughly twenty implemented registers. System instructions (ECALL, EBREAK, MRET, WFI) share the opcode and the ID space. An unimplemented CSR maps to the invalid ID, which raises an illegal-instruction trap. Aliases such as cycle and mcycle map to one ID, since one physical counter backs both.

In user mode, machine CSRs and MRET are illegal; cycle, time and instret stay readable.

Decode marks an illegal instruction, ECALL or EBREAK as an exception and sets mtval to the instruction word for illegal instructions. The instruction still receives a ROB entry, because traps are taken in order at commit, but it bypasses the issue queues and writes no register.

The Decode Register¶

assign decode_rdy = rename_rdy || decode_empty;

always_ff @(posedge clk)
    if (rst || flush)    decoded_insts[i] <= '0;
    else if (decode_rdy) decoded_insts[i] <= (fetch_vals != '0) ? decoded_insts_next[i] : '0;

The register loads a new group when rename accepts the current group or when it is empty, so a bubble never blocks the buffer, and it holds while rename stalls. The instruction buffer pops on the same edge. The register splits the path from the buffer through decode and rename into a scheduler entry.

Macro-Op Fusion¶

Two common RV32 pairs fuse: lui + addi builds a 32-bit constant, and slli + srli by the same amount zero-extends. In each pair the second instruction overwrites the first one’s result.

When both halves arrive in one fetch packet, decode merges them into lane 0 and drops lane 1:

Pair

Result

lui rd, u then addi rd, rd, i

lui rd with u + i precomputed

slli rd, rs, k then srli rd, rd, k

andi rd, rs with a mask of the low 32 - k bits

Both cases require lane 1 to write the register lane 0 wrote, read it as its first source, and carry no branch, prediction or exception. The merged op executes as a plain lui or andi, so execute needs no changes. The 20-bit add for u + i sits beside decode, off the ALU path.

Design Decision: Fusion Inside One Packet¶

A fused op occupies one ROB entry, one scheduler slot and one ALU cycle. At commit a fused bit makes minstret count two instructions. Fusion applies only within one 8-byte-aligned packet, so a pair starting on the upper word stays two instructions.

Limits¶

  • No compressed (C) instructions.

  • Fusion covers two pairs, within one packet.

  • WFI retires as a no-op with no low-power state.
