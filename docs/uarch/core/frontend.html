Frontend¶

The frontend turns predicted addresses into decoded instructions. Fetch reads two instructions a cycle along the path the branch predictor picks, and decode turns each pair into decoded ops for rename. Both are in order, and a flush clears both, since anything in the frontend during a mispredict is younger than the branch.

Fetch¶

pc ──> I-cache request ──> I-cache ──(n cycles)──> response
                                                     │
                                          predecode ─┤
                                          hold reg  ─┤
                                                     v
                                          instruction buffer (4 deep)
                                                     │
                                                     v
                                                  decode

Each request returns an aligned 8-byte group, two instructions; a PC on the upper word gives one valid lane. The RTL is fetch.sv, inst_buffer.sv and predecoder.sv in rtl/cpu/1-fetch/.

Why fetch doesn’t wait for the L1. Fetch sends the next request right away from registered buffer and FTQ space. If the L1 disagrees a cycle later, it kills that request and sends the right one in the same cycle a waiting design would have. That keeps predecode off the path to the I-cache address.

Predecode and the Hold Register¶

Predecode finds branches, JAL and JALR ahead of decode. A jump that writes x1 or x5 is a call, and JALR x0 through x1 or x5 is a return. Fetch uses this for FTQ entries, history and dropping lanes that can’t execute (slot 1 behind a taken jump).

A group predicted taken waits one cycle in a hold register so its redirect and packet leave together. The cache drops every stale response on a kill and returns the PC with the data, so fetch needs no epoch filter.

Direct Targets¶

JAL and conditional branches encode their target, so fetch adds the immediate to each lane’s PC. With no BTB entry, a JAL predicts taken to that target and a branch follows TAGE. It costs an adder per lane and the one-bubble L1 repair, but a branch seen for the first time no longer waits for a full redirect from execute.

Instruction Buffer¶

A 4-entry FIFO, one fetch group per entry (PC, lane valids, FTQ data, both words), in LUT RAM. It soaks up the cache’s variable latency and decode’s backpressure. Flush and reset only clear the pointers; an empty buffer shows invalid lanes, so a stale word is never decoded. A full buffer ignores a same-cycle pop when reporting space, which keeps decode’s ready off the cache request path.

Decode¶

Decode turns two words into two decoded instructions and holds them in one register that rename reads the next cycle. It also decides legality, so every illegal-instruction trap starts here. The RTL is rtl/cpu/2-decode/decode.sv.

Each instruction carries two operand pairs. src_0 is what the ALU or AGU computes on (registers, the PC or an immediate), and src_1 is the raw rs1 and rs2. That way a branch computes pc + imm on src_0 and compares on src_1 in one ALU pass. Stores use src_0 for the address and src_1_b for the data. Decode writes the architectural register into each source’s tag, and rename swaps in the physical ID.

CSR addresses compress to a 5-bit ID, and aliases like cycle and mcycle share one. Decode checks every opcode’s reserved fields, unknown CSRs and writes to read-only CSRs, and in user mode the machine CSRs and MRET. A bad instruction still gets a ROB entry with an exception, so the trap happens in order at commit.

The Decode Register¶

assign decode_rdy = rename_rdy || decode_empty;

always_ff @(posedge clk) begin
    if (decode_rdy)   decoded_insts[i] <= decoded_insts_next[i];
    if (rst || flush) decoded_insts[i].is_valid <= 1'b0;
end

It loads when rename takes the current group or when it’s empty, so a bubble never blocks the buffer. Only the valid bit resets, since nothing downstream reads an invalid lane. This register is also the cut between the buffer and rename.

Macro-Op Fusion¶

Pair

Becomes

lui rd, u then addi rd, rd, i

lui rd with u + i precomputed

slli rd, rs, k then srli rd, rd, k

andi rd, rs with a low 32 - k bit mask

When both halves land in one fetch packet, decode merges them into lane 0 and drops lane 1. Lane 1 has to overwrite lane 0’s register, read it as its first source, and carry no branch or exception. The merged op is a plain lui or andi, so execute didn’t change. It takes one ROB entry and one ALU cycle, and a fused bit makes minstret count two.

Fusion only happens inside one 8-byte packet, so a pair starting on the upper word stays two instructions. It measured +0.35% Embench and +0.10% CoreMark for 255 LUTs.

Limits¶

  • No compressed (C) instructions.

  • One group per request, and a group starting on the upper word leaves a lane empty.

  • The I-cache has no error signal, so there are no instruction access faults.

  • WFI retires as a no-op.
