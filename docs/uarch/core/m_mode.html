Machine-mode traps¶

This page describes how ORCA takes traps precisely: software observes the machine as if every older instruction finished and no younger one started. ORCA implements precise illegal-instruction, ECALL, EBREAK and address-misalignment traps, uncached/MMIO load and store access faults, direct mtvec entry, MRET, machine software, timer and external interrupts, and real FENCE.I cache maintenance. The ISA and software page defines the supported contract and how it is validated.

Related notes: Core, Stage 0: Branch prediction, Stage 8: Commit, Memory and ISA and software.

What is supported¶

Unknown or malformed instructions, ECALL, EBREAK, misaligned control targets and misaligned load and store addresses each report their ROB tag, cause and tval. At the head of the ROB they suppress retirement and side effects, update the trap CSRs, flush speculative state, and redirect to direct-mode mtvec. MRET restores the status bits and returns through the same dedicated redirect. System instructions use the scheduler’s port 2, issue only at the ROB head, and serialize at retirement.

Machine software, timer and external interrupts use the same commit-time path. The CPU exposes mie and a hardware-backed mip. The SoC supplies a 64-bit memory-mapped timer and combines the UART and FIN level interrupts into the machine external source.

AXI read errors on the uncached/MMIO data path report a precise load access fault. The LSU keeps the original effective address and ROB tag with the outstanding request. An error response completes that ROB entry as exceptional without writing its destination register, and cause 5 and the address enter the same oldest-exception record as other faults.

Stores use a one-shot authorization and response protocol. Once an aligned store reaches the ROB head, the ROB authorizes its matching LSQ entry exactly once. The LSQ may then send the write, and the ROB entry stays architectural state until the LSU returns the response. An OKAY response permits retirement, and an error marks the entry exceptional and reports cause 7 with the saved effective address. Pending interrupts wait behind an already-authorized store, so they cannot flush a write whose outcome is still unknown.

This is machine mode plus a minimal user mode that supports no-MMU Linux (see ISA). It is not every facility in the privileged architecture. The cacheable instruction and data line interface has no error bit, so it cannot report instruction access faults or cacheable load/store access faults. There is no supervisor mode, page translation, PMP, delegation or vectored mtvec.

The precise trap rule¶

An out-of-order machine may discover faults out of order, but it must expose them in program order. ORCA ties every discovered fault to its ROB tag and waits until that instruction reaches the ROB head.

Until then the instruction may be marked complete, but it cannot update the architectural register file, authorize a store, train the branch predictor or retire. Younger work stays speculative and is discarded when the trap is taken. This gives one architectural boundary:

                         v
                rob exception state
                         |
                  oldest instruction

                commit trap event

                         v
          csr update + full flush + redirect

Exception state beside the ROB¶

Each ROB entry holds one exception bit. A separate register remembers the oldest known excepting instruction:

oldest_exception = {
    valid,
    rob_tag,
    cause,
    tval
}

When a fault report arrives, its tag is compared with the saved tag, using the current ROB head as the circular age reference. The new report replaces the saved record only when it is older. The selector includes new reports even in a branch-recovery cycle and discards its winner only if that instruction is younger than the recovering branch, which preserves faults reported by surviving work on the recovery edge.

This is smaller than storing a cause and tval in all 64 ROB entries, and it keeps wide exception metadata out of the CDB and the normal commit-result mux.

Every ROB entry already stores a PC. When the saved tag reaches the head, the trap values are:

mepc   = rob[oldest_exception.rob_tag].pc
mcause = oldest_exception.cause
mtval  = oldest_exception.tval

The FTQ stays a frontend structure that holds prediction metadata and history checkpoints. It holds no exception state. A trap flushes the FTQ because all younger predictions are stale, but the FTQ takes no part in choosing or describing the trap.

Commit and redirect¶

Trap recognition produces a registered commit event. The ROB holds retirement and allocation while that event is pending, so the rare trap path does not become another same-cycle path from the ROB to the frontend. The event performs these steps across the registered commit boundary:

  1. suppress retirement and every side effect from the faulting instruction

  2. write mepc, mcause and mtval

  3. copy mstatus.MIE into mstatus.MPIE, then clear MIE

  4. record the previous privilege (M or U) in mstatus.MPP and enter machine mode

  5. clear the ROB exception record and flush younger backend state

  6. clear speculative frontend state and redirect to mtvec.BASE

In cycle one the ROB recognizes the faulting head and registers trap_commit_q. In cycle two the CSR bank consumes that event, and its combinational arch_redirect makes the BPU assert full_flush. The extra cycle is on the rare trap path only, and normal instructions never pass through it.

The redirect is a dedicated architectural redirect. It is never presented to SONAR as a fake committed branch, because that would train the BTB and TAGE with a trap-handler target. Unsupported mtvec mode values are forced to direct mode through WARL behavior.

An exception does not increment minstret. The faulting head cannot share its commit cycle with another instruction, because exceptions serialize. Older instructions may have retired in earlier cycles, but the faulting instruction and everything younger do not retire.

Return and CSR behavior¶

MRET is a real retired instruction followed by an architectural redirect. It sets the PC to mepc, restores mstatus.MIE from MPIE, and sets MPIE to one. The return flush uses the same dedicated redirect path as trap entry.

Decode checks the original 12-bit architectural CSR address before replacing it with a compact internal ID. This keeps distinctions such as writable mcycle and read-only cycle without widening the ROB and the scheduler. Unknown addresses and writes to architecturally read-only CSRs become precise illegal-instruction exceptions.

The status register implements MIE, MPIE and MPP. Unsupported privilege fields read as zero, and MPP is WARL with the values M and U (ISA). mepc and mtvec.BASE are aligned to four bytes. misa is a fixed WARL value, 0x4010_1101 (RV32IMA with U). The mandatory mvendorid, marchid, mimpid, mhartid and mconfigptr machine-information CSRs are present as read-only zero.

Synchronous exception sources¶

Load and store alignment is checked before a cache or AXI request is issued. A store is not marked ready at dispatch. Address generation first confirms that the store is valid, so a misaligned store cannot retire before the fault is known.

Interrupts¶

Interrupts use the same registered trap event, after all older instructions are precise. The CSR bank implements mie.MSIE, mie.MTIE and mie.MEIE, and the hardware-backed mip.MSIP, mip.MTIP and mip.MEIP. An interrupt is taken only when its local enable and pending bits are set and global mstatus.MIE is set. The priority is external, then software, then timer. Direct mtvec mode sends all three to the same handler.

The request is registered. The ROB sees a pending interrupt one cycle after the enable and pending bits allow it, and the request is held off for the cycle after any CSR write or trap, so a just-cleared enable is never bypassed. The ROB takes an interrupt before its valid head instruction retires and saves that head PC in mepc. If the ROB is empty, allocation provides the resume-PC anchor. A synchronous exception at the head wins over an interrupt, and an already-authorized store or a started FENCE.I finishes first. Stage 8 has the exact gating.

The SoC timer is a 64-bit mtime and mtimecmp AXI-Lite peripheral at 0x8000_2000. The same page has an msip register and a simulation-oriented external-interrupt source used by the architecture tests. The peripheral also exports mtime to the core for the read-only time and timeh CSRs, one cycle late. UART and FIN share the normal external interrupt input, so software checks their status registers to identify the source. Only FIN is asynchronous to the core, and only when it has its own clock. FIN latches completion or error as a level until its next accepted start, reset or soft reset. soc.sv passes that level through two core-clock synchronizer flops before combining it with the core-clocked UART and architecture-test external sources. The timer and software levels are direct core-clocked inputs.

WFI is a legal immediate-resume no-op. Stopping the clock is a power feature and is not needed for precise interrupt entry.

Access faults and fences¶

AXI read errors on the uncached/MMIO path return an error bit through the data router and the LSU, so loads can trap precisely without changing ordinary load latency. Cacheable memory is modeled as fault-free, and its line interface has no error response.

AXI write errors use the same response error bit, and store retirement is held until the response arrives. This also gives an ordinary FENCE the drain behavior it needs: by the time a fence reaches the ROB head, every older load has completed and every older store has received its response. AXI-path loads issue only at the ROB head, so device reads cannot pass older stores or fences and cannot execute on an unresolved wrong path. Cacheable younger loads stay speculative. This is not a general multi-master coherency mechanism.

FENCE.I starts a maintenance pass from the ROB head. The D-cache writes every dirty line to backing memory and invalidates its entries. The I-cache invalidates after the writeback is complete, then SONAR is flushed and fetch restarts at pc+4. The instruction cannot retire before that sequence finishes. The self-modifying-code test executes a cached instruction, overwrites its word through the D-cache, runs FENCE.I, and observes the replacement instruction after the refetch.

How it is tested¶

Every trap source has its own directed test. Trap tests place visible register writes and stores behind the faulting instruction and confirm that the handler sees none of them. Counter tests confirm that exceptions and interrupts do not retire instructions. Memory tests confirm that a misaligned operation sends no external request. The architecture tests are a separate gate that covers the same ground against the Sail model.

Normal programs never use the registered trap detour, so ordinary instruction latency does not depend on any of this.

Implementation limits¶

  • There is no exception queue and no second in-flight-instruction queue.

  • There is no supervisor mode, MMU, delegation or PMP, and user mode is minimal (no mcounteren, MPRV or TW).

  • There is no vectored mtvec.

  • There is no general cache coherence and no FIN cache-maintenance protocol.
