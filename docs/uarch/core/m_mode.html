Machine-Mode Traps¶

Traps are precise: software observes every older instruction complete and no younger instruction started. Faults arise out of order in decode, the ALU, the AGU and the LSU, and the ROB presents them in program order.

Cacheable memory returns no errors and cannot fault. The design has no supervisor mode, translation, PMP, delegation or vectored mtvec.

Mechanism¶

Each fault attaches to a ROB tag and waits until that instruction reaches the head. Until then the entry may be complete, but it cannot change state, authorize a store, train the predictor or retire.

                  v
          rob exception state
                  |
           oldest instruction
                  v
          commit trap event
                  |
                  v
   csr update + full flush + redirect

Design Decision: One Exception Record vs Per-Entry Cause¶

Each ROB entry has one exception bit, and one register holds the oldest known fault (valid, ROB tag, cause, tval). A new report replaces it only when older. Per-entry cause and tval storage would add area and wide fields to the result bus and commit mux. A flush clears the record, so wrong-path faults never reach the head.

When the tagged instruction reaches the head:

  1. The ROB registers a trap event, which stops retirement and allocation.

  2. The CSR bank writes mepc, mcause and mtval, copies MIE to MPIE, clears MIE, saves the previous privilege in MPP and enters machine mode.

  3. A full flush clears all speculative state, including the FTQ, and fetch restarts at mtvec.

The registered trap keeps this path off the ROB-to-front-end timing. The trap uses a dedicated redirect; routing it as a committed branch would train the BTB and TAGE with the handler address. A faulting instruction does not increment minstret.

MRET retires, redirects to mepc, restores MIE from MPIE and sets MPIE to one.

CSRs¶

Decode compresses the 12-bit CSR address into a short ID, and unknown CSRs or writes to read-only CSRs become illegal-instruction traps. CSR writes land one cycle after retirement, so retirement drives one register; CSR ops issue only at the head and nothing retires in that gap. mepc and mtvec are word aligned, MPP holds M or U, and misa reads 0x4010_1101.

Uncached Accesses¶

AXI read errors on uncached loads return through the data router and LSU, and the entry completes as faulting without a register write.

Uncached stores are one-shot. The store reaches the head, the ROB authorizes it once, the queue sends the write and waits, and an OKAY response permits retirement while an error raises cause 7 with the saved address. Interrupts wait behind an authorized store, so no flush can interrupt a write with an unknown outcome. Alignment is checked before any request leaves.

Interrupts¶

Interrupts use the same registered trap event. Each requires its enable and pending bits, plus mstatus.MIE in machine mode; U-mode always takes interrupts.

  • Bits: MSIE/MSIP, MTIE/MTIP, MEIE/MEIP.

  • Priority: external, software, timer. Direct mtvec sends all three to one handler.

  • The request is registered and suppressed after a CSR write or trap, so a just-cleared enable takes effect immediately.

  • mepc is the head’s PC. With an empty ROB, allocation admits one group to supply it.

  • A head exception takes precedence, and an authorized store or started FENCE.I finishes first (commit).

The timer is a 64-bit mtime and mtimecmp peripheral at 0x8000_2000, with a CLINT view at 0x8001_0000 for Linux. The UART and a test source share the external interrupt, and software reads their status registers to identify the source. WFI resumes immediately.

Fences¶

When FENCE reaches the head, older loads have completed and older uncached stores have their responses. Uncached loads issue only at the head, so device reads cannot pass older stores or execute on a wrong path.

FENCE.I writes back and invalidates the D-cache, invalidates the I-cache, flushes the predictor and restarts fetch at pc+4 (commit, caches). This covers one hart and its host, with no general coherence.
