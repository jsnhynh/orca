Stage 3: Rename¶

Rename removes false dependencies between architectural names. Each writer to a nonzero integer register receives a new physical register, and readers take the latest physical ID from the speculative register alias table (RAT). The ROB ID tracks instruction age and retirement. It does not store values.

Related notes: Stage 2: Decode, Stage 4: Dispatch, Stage 5: Issue, Stage 8: Commit and Core.

The idea¶

I keep values, scheduling and lifetime control in separate places. rename allocates physical destinations and publishes source IDs. The scheduler stores 32-bit entries that hold only identity and readiness. When an instruction is selected, it spends one register-read cycle reading the physical register file (PRF) and the immutable ROB-indexed context, and then enters the functional-unit input registers. The load/store queues keep their own address and store-data state, so they are not a general reservation station.

Where rename sits¶

These blocks are siblings inside core.sv. Every scheduler selection enters a clocked register_read stage inside issue.sv, and the reads that follow are combinational before the functional-unit input register.

core0
├── rename_stage                 rename: RATs, allocation, readiness, recovery
├── prf_inst                     physical_regfile: 64 physical values
├── payload_array_inst           payload_array: 64 immutable contexts
├── dispatch_stage               dispatch: classify and allocate ROB context
├── issue_stage                  issue: select, read PRF/context, form FU packet
│   ├── sched_inst               scheduler: 16 entries, three issue ports, CSR ROB-head-only
│   ├── alu_register_read        register_read: two held selections, then operand/context reads
│   ├── aux_register_read        register_read: port 2 (MDU, CSR, AGU)
│   └── lsq_inst                 lsq: twelve loads/twelve stores, filled by the AGU
├── execute_stage                execute: ALU/AGU/LSU/MDU/CSR registers
├── writeback_stage              cdb: two arbitrated completions
├── commit_stage                 rob: 64 in-order retirement lifetimes
└── csr_stage                    csr: architectural machine state

bpu_stage, fetch_stage and decode_stage sit upstream. cpu.sv wraps this core with the caches and the memory router.

RATs, free list, and busy table¶

There are 32 architectural names and 64 physical registers. Each RAT holds 32 six-bit IDs.

State in rename

Meaning

map_q

speculative RAT: newest destination allocated in program order

committed_q

committed RAT: architectural values established by retirement

free list

circular FIFO of free physical IDs: a head pointer, a tail pointer, a commit head, and two LUTRAM banks

busy_q

allocated values that have not successfully completed

owner_storage

per-ROB LUTRAM: destination, architectural name, stale destination, and checkpoint ownership (owner_writes_q, owner_pdst_q and owner_stale_q are simulation views)

checkpoint_*_q

FTQ-indexed branch RAT snapshots, each with the free-list head it was taken at

Reset maps x0..x31 to p0..p31 and queues p32..p63 in the free list. p0 always reads zero, is never allocated, and is never busy. Reset clears only PRF validity and bank metadata, and the data RAM contents are left alone.

A two-instruction group reads each source before updating its own destination. The younger lane sees an older lane’s new mapping, including read-after-write dependencies and repeated writes to the same architectural name. An accepted instruction that writes nothing still records a ROB owner but allocates no physical value.

Acceptance and stalls¶

A group advances only when physical allocation, ROB allocation and the target scheduler or load/store queue all accept it. Resource checks are atomic. A stalled group causes no RAT, free-list, busy or checkpoint update. A lone second decoded lane compacts into queue lane zero without changing its allocated identity.

Free list¶

Allocation pops consecutive entries from the free-list head. Lane zero takes the entry at the head and lane one takes the next, so a group needs no priority scan and the logic depth does not grow with the register count. The two banks hold alternate slots, so two pops always read different banks.

A group is admitted only when a registered credit says at least one register per lane is free. The credit is computed from the next-state pointers, so admission never depends on the group’s own destination fields. A group that needs fewer registers still waits until two are free, which costs one register of capacity.

Retirement pushes each committed writer’s stale ID at the tail, in program order, and a physical ID freed at an edge is available on the following cycle. The commit head advances with the tail and records the head position that the architectural state corresponds to.

Recovery sets the head to the value saved with the checkpoint, which returns every younger allocation to the free list at once. No allocation masks or per-register bitmaps are kept. A full flush sets the head to the commit head, which returns everything not yet committed. Entries between a restored head and the tail are never overwritten, because they hold only IDs that younger, squashed instructions allocated and that cannot have committed. Slots not written since reset read as their reset ID, so the RAM needs no reset. Completion readiness and accepted PRF write data bypass combinationally in the same cycle.

Completion and value storage¶

Every CDB packet carries both dest_tag (the ROB ID) and pdst (the physical destination). The ALU, the multiplier’s partial products, the divider transaction, the CSR unit, the LSU’s pending transaction and a store-forwarded load all preserve this identity.

rename qualifies the arbitrated completion against its live ROB owner, the matching physical destination and the selective-recovery age. An owned fault may mark the ROB entry ready and faulting but cannot publish a physical value. A successful first completion clears busy and enables its PRF write. Duplicate or stale writing completions do not write the PRF, clear busy or complete the ROB. A result that writes nothing still completes its live ROB owner.

Wakeup view¶

rename also produces completion_wake, which keeps only reset and flush plus duplicate suppression, and core.sv exposes it to the scheduler as wake_cdb_ports. It leaves out the recovery-age kill on purpose. In the recovery cycle a squashed producer’s broadcast can only wake younger consumers, which are squashed in the same cycle, and nothing issues then. Completion itself (the PRF write, the busy clear and the ROB) keeps the owner and recovery checks through the owner-checked cdb_ports.

Duplicate suppression compares both the ROB ID and the physical destination. An older lane with the same pair would pass the same owner checks and own the completion, so every live completion is also a wakeup, and a live result never strands its consumers. A stale result that reached the CDB would wake consumers before a valid write, and the FU squash rules and the LSU kill and epoch rules are what prevent that (see the limitations below).

The allocation-only owner metadata is read by the incoming ROB ID. Each completion compares the returned physical destination with its packet and checks owner validity, busy state and recovery age. The busy lookup uses the incoming physical ID in parallel with the metadata lookup, and the equality check makes this equivalent to indexing busy by the owner’s destination. An earlier eligible lane suppresses duplicates with the same ROB ID.

RAM-backed owner metadata¶

The 23-bit owner record holds writes-RD, architectural RD, physical and stale destinations, the checkpoint flag and the FTQ ID. It lives in multiport_lutram. Two allocation writers and four asynchronous reads support two completions and two retirements. Owner validity is separate and mutable. A stalled allocation, a flush or a recovery performs no metadata writes, and retirement reads the old metadata before a same-edge reallocation replaces it.

The shared memory uses one single-writer bank per write port and a live-writer selector per address. A resettable initialized mask makes every unwritten entry read as zero without resetting the RAM payload. Writes become visible after the edge, with no write-through bypass. The highest-numbered writer wins a collision, and rename asserts that accepted ROB allocation IDs are distinct. Disabled reads return zero and use address zero. There is no capacity handshake and no extra read cycle. Consumers own validity and lifetime, so flushing a consumer does not erase the RAM. Full-array diagnostic views exist only in simulation.

Physical register file¶

The PRF has two independently written 64-by-32 banks. A per-register live-writer table selects the current bank. Six asynchronous read ports serve:

  • issue ports 0 and 1 (ALU and branch): four operands;

  • issue port 2 (multiply/divide, CSR, or a memory op’s base and store data): two operands.

Disabled ports address zero, and same-cycle accepted writes bypass the RAM read. The PRF uses distributed RAM, not synchronous block RAM or UltraRAM, to keep the issue-to-functional-unit cycle contract. Data enables are not fabric-gated clocks.

Where values live¶

Committed and speculative integer values both live in physical_regfile. The committed RAT identifies architectural state, and retirement changes the map instead of copying values into a separate architectural array.

The LSQ captures store data itself, or captures it later from a qualified CDB broadcast. Its AGU selection reads the base from the PRF after a ready memory operation is selected. Memory responses and forwarding keep the load’s physical destination. The ROB keeps a 32-bit result per entry only for branch outcomes (the taken bit and the target), and register values live in the PRF.

payload_array holds one 106-bit uop_payload_t per ROB entry: PC, immediate, destination information, operation controls, FTQ identity and CSR ID. Validity belongs to the ROB and the queues, and only an accepted allocation writes context.

Retirement and recovery¶

Retirement supplies accepted in-order ROB IDs for every instruction, including stores and non-writing operations. A writer updates the committed RAT and frees its recorded stale physical destination, never its newly committed destination. Older readers have already retired by the time that newer writer can retire.

Each branch checkpoint holds its own and older-lane mappings, never younger-lane updates. The map snapshots use two single-writer distributed-RAM banks and a last-writer table, with one asynchronous whole-RAT recovery read. Either rename lane may write any FTQ slot, and if both address the same slot the younger lane wins. Snapshot contents are not reset in the RAM. A resettable initialized mask makes every logical snapshot read zero after reset until it is written. Flush and checkpoint invalidation keep the stored map, and checkpoint validity and the owner checks decide whether a recovery is legal.

Each checkpoint also records the free-list head at the moment it was taken, counting its own and older lanes’ pops. Recovery restores that RAT and head, which reclaims younger allocations, discards younger ROB owners and checkpoints using circular age, and lets surviving older completions finish. A full flush restores the committed RAT after accepted boundary retirements, and the committed physical values stay intact.

Retirement reaches rename one cycle after the ROB commits: retire_valid and retire_ids are registered at the rename input, so commit eligibility does not reach the committed RAT, the free list and the flush restore in a single cycle. A flush in the next cycle still includes that retirement, because the restore reads committed_d and the ROB commits nothing in a flush cycle. A retired ROB slot is reallocated no earlier than the cycle after retirement, when the delayed retirement still reads the old owner metadata, and its owner-valid clear comes before the new allocation’s set in the same cycle. Stale IDs return to the free list a cycle later. Global CPU reset initializes both the rename and PRF metadata.

Limitations¶

The pair (ROB ID, physical ID) is not an unbounded generation token. A response that arrives after both IDs were reused would look identical by identity alone. FU pipeline squash and the LSU’s pending-kill and epoch protection must keep such responses from being published. The owner check in rename is an extra guard that sits on top of those lifetime rules.

Tests¶

The focused rename and PRF bench, the dispatch recovery bench, the CPU smoke tests and the retirement-checked CoreMark run exercise this stage. fast_wakeup_tb drives the active scheduler.
