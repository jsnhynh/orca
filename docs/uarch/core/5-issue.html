Stage 5: Issue¶

Issue holds instructions until their operands are ready and selects ready work oldest first, while the ROB keeps retirement in order. This stage also contains the load and store queues, which hold most of the memory ordering logic.

The RTL is issue.sv, scheduler.sv, register_read.sv and lsq.sv in rtl/cpu/5-issue/.

Memory Op Flow¶

Each load and store receives a scheduler entry and a queue slot at dispatch. The scheduler issues it on port 2 once its registers are ready, register read supplies base, immediate and store data, the AGU computes the address, and the result fills the queue entry by ROB tag. The queues hold no operands and do not monitor the result buses.

Scheduler¶

Each entry is 32 bits: valid, ROB ID, two source IDs with used and ready bits, an issue class and the destination for fast wakeup. Values and controls are read after selection.

Design Decision: Tag-In-Scheduler vs Data-In-RS¶

The predecessor core used a data-in-RS design, where each reservation station entry holds its operand values and snoops the result bus for them, and ORCA’s early versions used five such stations. That approach is simple but grows poorly: every entry compares and captures data from every result. ORCA’s scheduler holds only tags and readiness bits, and values are read from the physical register file after selection. This costs one register-read cycle and reduced the wakeup logic and area enough to replace the five stations with one 12-entry scheduler.

Design Decision: Age-Only Selection on Port 2¶

Port 2 selects the oldest ready entry of any class. A memory-first rule on port 2 let younger loads delay an older multiply that later work depended on. CSR entries become ready only at the ROB head, so a ready CSR op is always the oldest instruction. A store needs both base and data ready.

Wakeup¶

A result that wins a result bus sets the matching ready bits, and an entry can be selected in the broadcast cycle. Each entry compares its sources against all six functional unit results, and the bus grant qualifies the matches at the end. ### Design Decision: Per-unit wakeup compare

Comparing against the two bus lanes placed the lane mux ahead of every tag compare, which was the core’s longest path at 175 MHz.

fu_wakes[fu] = '{is_valid: fu_cdb_gnts[fu] && fu_results[fu].is_valid &&
    !fu_results[fu].exception && !be_flush, pdst: fu_results[fu].pdst};

entries_woken[e] = wake_entry(entries[e]);
entry_ready[e] = !flush && entries[e].is_valid && !spec_pending_q[e] &&
    (!entries[e].rs1_used || entries_woken[e].rs1_ready) &&
    (!entries[e].rs2_used || entries_woken[e].rs2_ready);

An execute redirect leaves the scheduler unchanged; wrong-path entries issue until the back-end flush.

Age and Selection¶

A pairwise matrix records allocation order. One of any two entries is older, so the matrix stores only its upper triangle. For the ALU ports, the ready entry with no older ready ALU peer is rank 0 and the entry with exactly one is rank 1; ports 0 and 1 take those. Port 2 takes the ready MDU, CSR or memory entry with no older ready peer of those classes.

Free slots load their lane’s incoming entry every cycle and only the valid bit waits for dispatch, which keeps the dispatch handshake off the entries and the matrix. The ordered-window alternative, where position encodes age, appears in results.

Register Read¶

Each selection spends one cycle reading the register file and its payload in parallel and then becomes the functional unit packet. Each ALU lane holds one selection and accepts the next when empty or when its packet moves into the ALU, so two selections per cycle run without bubbles. Under backpressure the lane holds, and the scheduler removes an instruction only when its selection is accepted.

Operands come from the register RAM with forward ports for each ALU’s current and held results and for the load result register. Every producer falls into one of two groups. Producers that wake consumers from the result bus (multiply and divide, CSR, non-fast ALU ops) write the RAM before their consumers read it. Producers that wake consumers earlier (fast ALU, held results, speculative loads) supply the value through a forward port. This keeps the bus lane mux off the ALU-to-ALU loop. A simulation assertion stops the run if a register is read in its write cycle without forward port coverage.

ALU ops have fixed latency, so they announce their destination as they enter the ALU and a dependent can select in that cycle. The destination is stored in the scheduler entry at dispatch, which keeps the payload read off the select and wakeup loop. Branches, jumps, multiply and divide and system ops wake on completion.

Speculative Load Wakeup¶

The LSU announces a load’s destination one cycle after sending its request, before the hit is known. ALU, branch and memory consumers can select on that announcement with a speculative flag, and a check arrives one cycle later. On a hit the consumer takes its operand from the LSU result register through forwarding. On a miss register read drops the selection, every entry waiting on that register loses its readiness and keeps its age, and the entries reissue on the real broadcast.

The gain appeared once every instruction built on the unverified load carried the flag, so a miss cancels the whole chain.

Load/Store Queue¶

lsq.sv holds both queues, ordering, forwarding, draining and the flush that keeps committed stores.

The load queue has 12 circular entries: allocated in order, issued out of order, freed at retirement. The store queue has 12 entries in a strict FIFO that drains in order. A load keeps its entry until retirement so a late store address can still check it. A store leaves once its committed request is accepted.

Within a queue, age is FIFO position. Between queues, each load records how many stores were older at allocation, and each store pop decrements the count. A store is older than a load when its queue position is below that count. This uses one small counter per load in place of a 576-bit age matrix; a simulation-only matrix and an assertion confirm agreement.

ORCA does not merge store bytes with cache bytes; a partial overlap waits. Masking each candidate that has a younger overlapping store finds the youngest overlap without a serial mux chain across twelve stores on the cache request path.

Load Speculation¶

A load waits on older stores with unknown addresses only when its bit is set in a 256-entry one-bit table indexed by PC. Violations are caught as follows:

  1. On the cycle after a store address arrives, the queue compares it with every younger load that has executed.

  2. The oldest overlapping load is the violation, and its ROB ID goes to the ROB.

  3. Its table bit sets.

  4. The ROB refetches from that load when it reaches the head (commit).

A sweep clears one table entry every 512 cycles, so a load that stops colliding regains speculation. A stale bit can delay a load and never produces a wrong result.

Memory Arbitration¶

One memory op reaches the LSU per cycle. Loads take priority, since committed stores are already architecturally complete and loads sit on dependency chains; pointer-chasing loops show the effect directly. When the store queue nears full, stores take priority so draining continues.

Design Decision: Early Load Request from the AGU¶

A load whose table bit permits speculation and whose base keeps it in the cacheable window sends its cache request directly from the AGU in the same cycle. It still passes the forwarding check one cycle later; a forward or stall result cancels the cache response. This removes one cycle of load-to-use latency for most loads.

Uncached loads wait for the ROB head with no pending stores, so device registers see no speculative reads.

The forward check runs only for the selected load, 1 x 16 compares in place of 16 x 16, using word-match bits from a load-by-store matrix updated as addresses arrive. Selecting a matrix row costs less than muxing out an address and comparing it against every store.

Store Authorization¶

Stores compute addresses and data speculatively and stay invisible until the ROB commits them. Commit issues tokens: one per cacheable store as it retires (up to two per cycle), and one for an uncached store or atomic at the head (commit).

The queue finds the first and second eligible stores in parallel from registered state, and the late token selects between them. A running rank across the queue would end with the token count on a long chain. The token is registered before it reaches the memory request, which breaks the path from commit through authorization and the router to the cache write enable.

Flush¶

The queues respond only to the back-end flush. Every load is invalidated and committed stores remain. Committed stores are older than every load, so the flush needs no age comparison.

stq_committed <= stq_flush_keep;          // in-order committed prefix
stq_tail      <= stq_add(stq_head, stq_flush_count);
ldq[i].is_valid <= 1'b0;                  // every load dies

Limits¶

  • Load speculation uses a one-bit table, with no store-set predictor.

  • A store generates its address only once its data is ready.

  • A partial overlap stalls the load.

  • One memory op issues per cycle across both queues.

  • A blocked store at the head blocks all draining.
