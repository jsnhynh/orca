A extension: atomics¶

The A extension adds word-sized atomic memory instructions. ORCA implements both halves defined for RV32: Zalrsc, which provides LR.W and SC.W, and Zaamo, which provides nine read-modify-write instructions: AMOSWAP.W, AMOADD.W, AMOXOR.W, AMOAND.W, AMOOR.W, AMOMIN.W, AMOMAX.W, AMOMINU.W and AMOMAXU.W. They share the AMO opcode and carry the operation in the upper five bits of funct7. This note follows an atomic from decode to retirement.

Semantics¶

All atomics are word-sized and naturally aligned. ORCA has one hart, and each atomic executes non-speculatively. The result is that every atomic is indivisible, so the aq and rl ordering bits need no extra hardware and are ignored.

The reservation is one word. A completed LR.W sets it. An SC.W clears it whether or not it succeeds. A store or AMO write to the reserved word clears it, and so do trap entry and MRET. A flush after a mispredicted branch or a load replay does not clear it. An LR.W runs only at the ROB head and a wrong-path store never reaches memory, so nothing on the wrong path can have touched the reserved word, and keeping the reservation lets an SC.W behind a mispredicted branch still succeed. A failed SC.W makes no memory access. An LR.W that faults leaves no reservation.

Path through the pipeline¶

Decode. An atomic is legal when funct3 is W, funct5 names a known operation, and rs2 is zero for LR.W. Decode keeps funct7, whose upper five bits are the operation. The ignored aq and rl bits travel along unused.

Dispatch. An atomic takes a scheduler entry and a store queue slot, because it writes memory like a store (Stage 4). The scheduler issues it on port 2 and the AGU computes its address. When the address and the rs2 data reach the store queue, the AGU marks the entry amo_resolved for the ROB.

Authorization. The ROB authorizes an atomic only when it is the oldest instruction, never by lookahead, and only when amo_resolved is set. At that point every older store has already completed, so the atomic runs non-speculatively. Interrupts wait while it is authorized, which keeps its read and its write together (Stage 8).

Store queue. The atomic sits in the store queue with its address and rs2. rs2 is not the value left in memory, so an atomic never forwards to a load. A younger load of the same word waits until the atomic leaves the queue; a load of another word can still forward from an older plain store across the atomic (Stage 5).

LSU sequencer. The store queue hands the atomic to the LSU as an OPC_AMO packet. A sequencer takes over the cache port, and while it is busy no other memory request is granted.

LR.W skips the write. SC.W checks the reservation when it is taken: on a hit it goes straight to A_WRITE with rs2 and returns 0; on a miss it goes to A_DONE and returns 1 without touching memory. A read error skips the write. The read and write come from registers and the request select is a flop, so an atomic adds one 2-to-1 mux level to the cache request and nothing to its control. The ALU function (amo_result in lsu.sv) works one cycle after the read from registered inputs, so it is not on the cache response path.

Retirement. The LSU reports the finished atomic to the ROB on store_result, and only then does the entry retire. The old word travels on the common data bus as the result for rd.

Exceptions¶

A misaligned LR.W raises load address misaligned (cause 4) and a bus error raises load access fault (5). For SC.W and the AMOs the causes are store/AMO address misaligned (6) and store/AMO access fault (7). The faulting address is reported as tval. A faulting atomic writes nothing.

Memory regions and coherence¶

Atomics work on cacheable DDR and on the uncached DMA region. The caches do not snoop, so a write by the host or a DMA master to the same word is not ordered against an atomic.

Flush behavior¶

A flush cannot reach an authorized atomic, because the ROB holds interrupts and traps until it retires; a simulation assertion checks this. If one did, the sequencer would finish the memory side like a committed store and publish nothing.

Tests¶

amo_test and amo_random_test run the instructions in the CPU testbench, and lsu_tb and lsq_tb check the sequencer, the store queue behavior and the load interlock. The RISC-V architecture tests for Zaamo (the nine AMOs) and Zalrsc (lr.w, sc.w) pass through cpu_tb, with the reference model configured for AMO arithmetic, an eventual reservation, a one-word granule, and misaligned atomics raising address-misaligned exceptions.
