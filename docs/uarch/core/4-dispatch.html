Stage 4: Dispatch¶

Dispatch sends each renamed instruction to the scheduler, assigns memory ops a load or store queue slot, and writes the ROB entry, all in the rename cycle. Queue ready signals come from registered occupancy, so no pipeline register sits between rename and the queues.

The RTL is dispatch.sv and payload_array.sv in rtl/cpu/4-dispatch/.

Destinations¶

Every instruction without an exception enters the 12-entry scheduler. Memory ops also take a queue slot:

Instruction

Destination

ALU, branch, multiply and divide, CSR

scheduler

loads

scheduler (for address generation) and the load queue

stores and atomics

scheduler and the store queue

Each scheduler entry carries an issue class (ALU, MDU, CSR or memory) that determines its port. Branches use ALU entries, and one ALU computes target and condition together.

An instruction with an exception receives only a ROB entry, which keeps the trap precise.

Routing¶

Rename compacts a lone instruction into slot 0, which leaves two queue cases: both slots to one queue take channels 0 and 1, and slots to different queues each take channel 0 of their queue. A load or store needs a free scheduler lane and a free queue channel.

Routing uses the class decoded from the opcode, ahead of the valid bit, which arrives late from rename. Lane 1 is never valid behind an invalid lane 0, so the route is correct whenever a write occurs. The source lane comes from the decode register; a ROB tag comparison would pull the ROB grant through a compare into the payload mux and scheduler fields. A simulation assertion checks that both methods agree.

Backpressure¶

One handshake covers rename, ROB allocation and queue insertion, so a group enters entirely or waits entirely. Queue readiness comes from registered free counts, so a slot freed on this edge appears on the next cycle and readiness never depends on same-cycle selection. That ready signal is the only stall source for the front half of the machine.

ROB Entry and Payload¶

Dispatch writes the ROB entry in the cycle rename assigns the tag, with the fields commit needs: PC, destination, opcode, CSR ID and exception flag. Results arrive later on the result buses. Exception reports use a separate port with ROB tag, cause and tval, so the ROB tracks the oldest exception apart from completion.

Design Decision: Payload Array vs Wide Scheduler Entries¶

The fields that stay fixed after dispatch (execution controls, immediate, physical destination, FTQ identity, 106 bits) go to the payload array, indexed by ROB ID. Scheduler entries shrink to about 20 bits plus the ROB tag. The payload array uses one single-writer LUT RAM bank per lane with a last-writer table, and it has eleven asynchronous read ports: three for retirement and eight for issue.

Wakeup Coverage¶

Every result reaches a waiting source exactly once, by one of three routes:

  1. The producer finished earlier, and the busy table reports ready.

  2. The producer finishes in the rename cycle, and rename sees the same-cycle register write.

  3. The producer finishes after the consumer is queued, and scheduler wakeup catches it.

Recovery¶

While an execute redirect is pending, rename reports not ready, so correct-path work cannot enter a queue that still holds wrong-path work. The back-end flush empties everything on the cycle after the branch retires, with no selective removal.

Limits¶

  • No buffer between rename and the queues, so a group that does not fit stalls rename.

  • Multiply and divide share the scheduler with ALU work and issue on port 2.

  • Dependence prediction is a one-bit table that holds back loads that previously conflicted with a store (issue).
