ISA and software contract¶

ORCA implements RV32IMA_Zicsr_Zifencei and runs in machine mode, with a minimal user mode. RV32 denotes 32-bit integer registers and addresses, I the base integer ISA, M multiply and divide, and A word atomics (Zalrsc’s LR.W and SC.W, and Zaamo’s nine AMO*.W). Zicsr defines the CSR instructions and Zifencei defines FENCE.I.

This page says what software may rely on. The pipeline mechanisms are on the Core page, and precise traps are on the Machine-mode traps page.

Instruction-to-hardware map¶

Decode in rtl/cpu/2-decode/decode.sv recognizes two instructions in parallel and turns each into an instruction_t. The opcode and function fields choose the path below.

Instruction group

Execution path

Architectural completion

integer ALU, LUI, AUIPC

scheduler port 0/1 -> either ALU -> CDB

ROB writes rd at commit

conditional branches

scheduler port 0/1 -> ALU compare/target -> BPU side band

ROB retires alone and trains SONAR

JAL, JALR

scheduler port 0/1 -> ALU target -> BPU side band; CDB forwards pc+4

ROB writes pc+4 and retires alone

loads

scheduler port 2 -> AGU -> load queue -> D-cache or AXI -> LSU -> CDB

ROB writes sign/zero-extended result

stores

scheduler port 2 -> AGU -> store queue; wait for ROB authorization -> LSU

retire only after write response

atomics

scheduler port 2 -> AGU -> store queue; ROB authorizes only at its head -> LSU read, modify, write -> CDB

retire after both the write response and the old word

multiply

scheduler port 2 -> four-cycle multiply pipeline -> CDB

ordinary ROB register write

divide/remainder

scheduler port 2 -> iterative divider -> CDB

ordinary ROB register write

CSR/system

scheduler port 2, only at the ROB head -> CSR unit

issue at ROB head and retire alone

FENCE

ALU completion

in-order retirement waits behind older memory work

FENCE.I

ALU completion -> ROB/L1 maintenance handshake

D-cache writeback, both L1s invalidated, restart at pc+4

An unsupported or malformed encoding still gets a ROB entry. Decode creates a ready, exception-marked entry that holds the raw instruction for mtval, and commit takes the illegal-instruction trap when that entry becomes the oldest.

Machine-visible state¶

rtl/cpu/8-commit/csr.sv implements these machine facilities:

  • mstatus, misa, mie, mtvec, mscratch, mepc, mcause, mtval, and hardware-backed mip;

  • mcycle/mcycleh and minstret/minstreth, including the read-only cycle and instret aliases;

  • read-only-zero mvendorid, marchid, mimpid, mhartid, and mconfigptr;

  • legal WARL-zero mstatush for RV32;

  • direct-mode trap entry, MRET, and software, timer, and external interrupts.

Only mstatus.MIE, MPIE, and MPP exist. mie/mip expose only MSI, MTI, and MEI. mtvec and mepc are forced to four-byte alignment. misa is the fixed RV32IMA + U value, 0x4010_1101.

User mode. No-MMU Linux runs user code in U-mode. It returns to U-mode with mret and MPP = U, and it expects system calls as cause 8. ORCA tracks the current privilege (M or U) in csr.sv, and MPP is WARL with the values {00, 11} (01 and 10 read as 00). A trap records the previous privilege in MPP and enters M, and mret returns to MPP and leaves MPP = U. In U-mode, decode makes machine CSRs (address bits [9:8] non-zero) and mret illegal, ecall reports cause 8 (11 in M), and the user counters (cycle, time, instret) stay readable. Machine interrupts are enabled in U-mode whatever mstatus.MIE says. There is no PMP, MPRV or mcounteren, so U-mode is not a protection boundary here. user_mode_test covers it. WFI is legal and resumes immediately, and it does not stop the clock.

The SoC supplies a memory-mapped 64-bit mtime and mtimecmp block, a software interrupt bit and external interrupt sources. These are peripherals and not CPU CSRs, and the Memory page lists their addresses. The read-only time and timeh CSRs (0xC01 and 0xC81, used by rdtime and rdtimeh) alias that mtime. The peripheral exports its count to the core, which registers it, so a read lags mtime by one cycle. Writing them is an illegal instruction (time_csr_test).

Atomics¶

All atomics are word-sized and naturally aligned, and each one executes only when it is the oldest instruction. The A extension page describes the instructions, the reservation, the exceptions and the pipeline path.

Precise exception boundary¶

The implemented synchronous causes are illegal instruction, breakpoint, machine-mode ECALL, taken control-target misalignment, load/store/AMO address misalignment, and uncached/MMIO AXI load/store/AMO access faults. A fault is tagged when it is detected and changes architectural state only at the ROB head.

The cacheable line interface has no error response, so instruction access faults and cacheable load/store access faults cannot be generated. There is no supervisor mode, MMU, PMP, delegation, compressed instructions, floating point or vector ISA, and software must not expect any of them.

Software support¶

ORCAstrator is the freestanding software under sw/. It provides startup code, the linker script, UART output, counter helpers, FIN control and small demos. There is no hosted C library; the no-MMU Linux under sw/linux is the operating-system environment. Programs enter at the boot ROM and use the addresses on the Memory page.

Validation¶

The pinned RISC-V ACT4 source is under third_party/riscv-arch-test, and ORCA’s device configuration is sim/act/orca-rv32ima-zicsr-zifencei. The generated suite contains RV32I, RV32M, Zaamo, Zalrsc, Zicsr, Zifencei, ExceptionsSm, and InterruptsSm tests (67 programs). Each program is one image linked at 0x1000_0000, the bottom of the DDR window, and its halt macro leaves a pass or fail word in x31 and in the last word of the DMA region. make act loads each image into the DDR model, starts it through the boot ROM the way the board’s host does, and passes 67/67 through cpu_tb. The Sail reference is configured to match the implemented atomics: AMO arithmetic, eventual reservations, one-word reservation granule, and misaligned LR/SC/AMO raising an address-misaligned exception (cause 4 for LR, cause 6 for SC/AMO). The machine has no misaligned load/store support, so the Misalign tests are not selected.

make isa-prereqs checks the compiler, mise, and Sail model. make act generates Sail-backed self-checking programs and executes them. Generated files are cached below build/act/generated/<fingerprint>; the fingerprint covers the ACT revision, extension list, ORCA configuration/macros, wrappers, Sail adapter, and selected toolchain identity, so a meaningful input change creates a new suite. The simulation’s images are the board’s images: make act-board packs the same ELFs as flat binaries, the board host reads the mailbox word, and all 67 pass on the board.

Directed RTL and assembly tests additionally exercise serialization, CSR write/read pairs, trap side-effect suppression, memory errors, interrupts, and self-modifying code across FENCE.I. Passing these tests is evidence for the implementation described here. It is not RISC-V International certification.
