Stage 7: Writeback¶

Writeback is the smallest stage in the core, and its broadcast is the one every other backend block observes. Five slots can produce CDB results: two ALUs, the LSU, the MDU and the CSR unit. The arbiter has six source positions because the AGU occupies slot 3, but that source is tied invalid, because the AGU returns addresses directly to the LSQ. The common data bus has two lanes, and this stage decides who gets them.

Related notes: Stage 6: Execute, Stage 8: Commit, Stage 5: Issue and Stage 3: Rename.

Who is listening¶

A single CDB broadcast fans out to almost every stateful block in the backend:

raw_cdb_ports ──> rename             qualify live (rob id, physical id)
                     ├──> physical_regfile write value and same-edge bypass
cdb_ports[0..1] ─────┼──> scheduler  capture physical source readiness
                     └──> rob        mark entry ready, store result

The load and store queues do not listen, because the AGU fills their addresses and store data by ROB tag. The fanout is the reason the arbiter stays simple: logic such as ROB age comparison or priority by instruction type would sit in front of every one of those consumers.

Round-robin, done in parallel¶

The obvious implementation is a priority walk that starts after the last grant, but that builds a serial chain. The arbiter keeps a registered ordering matrix instead:

priority_before_q[i][j]   // source j currently precedes source i

Ranking is then a parallel reduction:

older_sources[i]  = fu_results[j].is_valid & priority_before_q[i][j];
rank_select[0][i] = fu_results[i].is_valid && !(|older_sources[i]);   // oldest
rank_select[1][i] = fu_results[i].is_valid && exactly_one(older_sources[i]);

exactly_one is the v & (v-1) power-of-two test over six bits, which is a shallow cone of logic and not another priority walk.

The matrix advances to the source after the last grant. Every comparison inside precedes_after_last is between elaboration-time loop constants, so only the one-hot last_select chooses which precomputed ordering becomes the next registered state.

Reset orders source 0 first. There is no flush input, because the ordering is a fairness preference and is not architectural state. Flushed functional units remove their own valid results, and keeping the rotation cannot change any instruction’s value or retirement order.

One-hot output muxing¶

Results are selected by mask-and-OR rather than a dynamic index:

cdb_port_bits[port] |= fu_result_bits[i] & {WB_BITS{rank_select[port][i]}};

Encoding the rank to an index and then decoding it again would rebuild a serial mux right after the rank calculation, on a path that already fans out across the whole backend.

Fairness without starvation¶

The arbiter has no ROB-age priority, so in principle younger results could starve an old one. They cannot, because functional units hold ungranted results. A unit that is not granted keeps its result and keeps asserting is_valid, which blocks its own input register and eventually backpressures its issue queue. Round-robin therefore guarantees eventual service. With five CDB producers and two lanes, a continuously valid result is selected within at most three arbitration cycles. Progress comes from the structure and does not depend on ROB age.

Exceptions on the bus¶

writeback_packet_t carries an exception bit alongside the result:

typedef struct packed {
    logic [TAG_WIDTH-1:0]     dest_tag;
    phys_reg_id_t             pdst;
    logic [CPU_DATA_BITS-1:0] result;
    logic                     is_valid;
    logic                     exception;
} writeback_packet_t;

This lets one broadcast mark a ROB entry as both ready and faulting. The user of this bit is a load whose memory response reported an error. Decode faults, misaligned addresses, branch-target faults and store responses use their own side-band completion paths. In every case the detailed cause and tval travel on a separate *_exception report port, so the CDB stays narrow, and the ROB waits to trap in order at commit.

What does not use the CDB¶

  • AGU results go straight back to the LSQ. Address generation has no register destination.

  • Store completions are reported on store_result, so the ROB learns the memory response arrived without consuming a CDB lane.

  • Committed ownership changes the committed RAT at retirement. Values are already in the PRF from a successful qualified completion, and retirement does not copy them into a separate architectural data array.

Known limits¶

  • Two lanes serve six sources, so a burst of simultaneous completions serializes.

  • There is no general bypass between functional units. Register read forwards the two ALUs’ computed and held results and the LSU load result, and everything else reaches a consumer through the CDB and the PRF write bypass. The scheduler can select a resident consumer in the cycle of a matching CDB broadcast, and it keeps wakeups that arrive while an entry is stalled.

  • The exception bit is the only status carried, so cause information needs the side-band report ports.
