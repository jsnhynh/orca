Memory¶

ORCA has two memories: a 4 KiB boot ROM at address zero and the board’s DDR. ORCA has no on-chip RAM, no L2 cache and no DDR controller of its own. The CPU’s L1 caches refill from DDR through a line bridge, and a 16 KiB region at the top of the DDR window is reserved for uncached traffic from the CPU, FIN and the host.

Simulation and the board use the same map. The DDR is a model in simulation (ddr_axi_mem) and the processing system’s DDR on the KV260, and both programs and data live there. Image loading is a simulation feature only; on the board the host writes the image into DDR before it releases the CPU.

This page covers request routing and the address map. The L1 caches, the boot ROM and DDR and main memory have their own pages.

Related notes: SoC and L1 caches.

Mental model¶

CPU instruction/data caches
        |
        | 128-bit line request
        v
  memory.sv route -------------------> boot_rom.sv        0x0000_0000-0x0000_0fff
        |
        +----------------------------> ddr_line_bridge     0x1000_0000-0x1fff_ffff
        |                                    |
        |                                    v
CPU uncached + FIN DMA + host AXI --> id remap, width    ---> shared ddr mux ---> M_AXI_DDR
        (DMA region only)             converter, address

The cached path and the uncached path are two ways into the same DDR. They meet at a two-way mux that feeds the single 128-bit M_AXI_DDR master. A write through AXI therefore lands in the same bytes a later cache-line read returns, which is how the host loads a program before releasing the CPU. The two paths never cache the same bytes: data accesses to the DMA region always use AXI, and the cache never refills a data line from it.

CPU address paths¶

rtl/common/soc_pkg.sv defines the private memory interface used below the CPU caches. A request contains:

  • valid: the request is being offered;

  • we: one for a write and zero for a read;

  • a 32-bit byte address;

  • 128 bits, or 16 bytes, of write data; and

  • one byte-enable bit for each of those 16 bytes.

A transfer occurs only while valid and ready are both one. Reads later return a 128-bit response with a one-cycle valid pulse. There is no response ready signal, so the memory side must not produce a response until the path back to the CPU can hold it. Line writes have no separate acknowledgement.

Before this interface, rtl/cpu/cache/dmem_router.sv separates CPU data addresses. Normal data goes through the D-cache and reaches this line path. The uncached DMA region and device addresses go through the CPU’s AXI port. Instruction fetch always uses the line path, including for code that sits in the DMA region.

Top-level routing: rtl/mem/memory.sv¶

memory routes each CPU line request to one of three places by address:

  1. The boot ROM, for addresses below 0x0000_1000.

  2. The DDR line bridge, for addresses inside the DDR window.

  3. An unmapped responder, for everything else. Reads return zero two cycles after they are accepted, as the boot ROM does, and writes are dropped.

The module sends valid to exactly one target and returns that target’s ready. Reads return later, after the original address is gone, so boot_pending_q, ddr_pending_q and unmapped_pending_q record which target owns the next response. A newly accepted read sets its bit after the old response has cleared it.

The line port assumes one read in flight, because the cache arbiter remembers only one owner for the next response. The boot ROM and the unmapped responder answer two cycles after a read is accepted, and DDR answers much later, so memory enforces the rule itself. A DDR read is accepted only when no ROM or unmapped read is outstanding, and no read of any kind is accepted while a DDR or unmapped read is outstanding. ROM reads may follow each other, because the ROM returns them in order. Writes are never held back. A design that assumed one-cycle responses would let a DDR read slip in behind a ROM read and hide its response, which would deadlock the I-cache. soc_ddr_tb catches that case.

The CPU request and response are direct core_clk wire aliases. The CPU, cache, memory, and AXI fabric intentionally share that clock; only FIN crosses into the memory fabric through its AXI CDC bridge.

The uncached DMA region¶

The AXI crossbar’s memory target covers only the DMA region, 0x1fff_c000 to 0x1fff_ffff. Every other address below 0x8000_0000 has no target, and the crossbar answers it with a decode error. Requests from the CPU’s uncached port, FIN and the host reach memory through three small steps:

  1. axi_id_remap narrows the crossbar’s six-bit IDs to one bit, so the merged ID still fits the two-bit M_AXI_DDR ID.

  2. axi_dw_converter widens the 32-bit beats to 128 bits. Narrow beats keep their size and strobes; bursts pass through beat by beat.

  3. The address is rewritten from ORCA’s address to the processing system’s (DDR_PHYS_BASE plus the offset into the window).

An axi_mux then merges this path with the line bridge’s master. Responses return by ID, so each source sees only its own.

The line bridge and stale lines¶

ddr_line_bridge turns line requests into AXI4 traffic on the shared master. It keeps one read line buffered, which is what lets the four beats of a cache line be served from one burst. Writes through the bridge update or drop that buffer, but writes that arrive another way do not pass through it. The bridge’s invalidate input clears the buffer in two cases: while the CPU is stopped, because the host rewrites DDR directly over the processing system’s own path, and whenever a write on the DMA path completes, because that data is now in DDR behind the bridge. A line that is already in flight finishes first, and the refill that follows reads DDR again.

The L1 and FIN activation adapters select XPM under SYNTHESIS and the generic adapter otherwise. The boot ROM uses an XPM ROM image under SYNTHESIS and a generic array otherwise.

Verification boundary¶

memory_boot_tb checks the boot ROM (including back-to-back reads), the unmapped responder, DDR line reads and byte-enabled line writes, single, narrow and burst accesses on the DMA region through the width converter, the stale-line behavior with and without the invalidate, and mixed cached and uncached traffic under random DDR stalls. ddr_line_bridge_tb checks the bridge alone against a model. soc_ddr_tb runs a program from DDR with every access size, 64 KiB through a 16 KiB cache, and code written into DDR and run after fence.i.

make xsim tb=orca_sram_1rw_xpm_tb checks zero initialization, synchronous reads, write-first byte writes, and disabled-output hold for an L1 bank. make xsim tb=boot_rom_xpm_tb checks the initialized boot-ROM words.

The normal Make/Verilator run exercises generic storage, including with TARGET=xilinx; make xsim defines SYNTHESIS and uses Vivado’s XPM memory library. Passing the generic fallback alone does not establish native XPM behavior. orca_ram_tb checks the reusable RAM collision and mask rules. The asynchronous SoC test exercises the FIN AXI crossings.

These tests establish functional RTL behavior. They do not establish BRAM inference, FPGA utilization, maximum frequency, or power.

All ranges in the RTL are half-open: the start belongs to the range and the end does not. The five peripheral pages are decoded in rtl/bus/axi_peripheral_subsystem.sv. rtl/common/soc_pkg.sv holds their base constants plus the addr_in_dma_buf range helper.

The boot ROM covers the first 4 KiB only for CPU line traffic. CPU writes below 0x0000_1000 are accepted but ignored because the selected target is a ROM.

Linux must not use the DMA region. The board device tree sets the memory node to 0x0fff_c000 bytes, which stops the kernel’s memory 16 KiB short of the end of the window.

Who can reach what¶

CPU cached line port ---------------------------> boot ROM or DDR

CPU uncached AXI ----+
FIN DMA AXI ---------+--> main AXI crossbar ----> DMA region or peripherals
PS host AXI --------+

The CPU cache subsystem sends normal program/data traffic over its private 128-bit line port. The CPU’s address router sends the DMA region and MMIO over 32-bit AXI instead. FIN and the host also use AXI.

CPU loads to either AXI region must reach the ROB head before issuing. This prevents speculative peripheral read side effects and orders them after older stores and fences. Cacheable loads keep their existing speculative behavior.

The crossbar’s memory target covers only the DMA region, so every other AXI address below 0x8000_0000 is a decode error. That restriction is what lets the CPU and FIN share buffers without treating DDR as an uncached AXI RAM.
