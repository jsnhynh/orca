Memory¶

ORCA has two memories: a 4 KiB boot ROM at address zero and the board’s DDR, reached through the PS’s DDR controller. The only other on-chip RAM is the L1 caches, and there is no L2.

Design Decision: DDR Only¶

An earlier SoC also had on-chip RAM. It was removed so that simulation and the board use one memory map: the DDR is ddr_axi_mem in simulation and the PS DDR on the KV260, and the host writes the image into it before releasing the CPU.

Design Decision: Uncached DMA Region vs Coherence¶

Cached and uncached traffic reach the same DDR through a two-way mux on the 128-bit M_AXI_DDR master. Data accesses to the DMA region always use AXI, so the two paths never cache the same bytes and need no coherence.

Ranges in the RTL are half-open. The constants live in rtl/common/soc_pkg.sv, and the software and the host tool carry copies. Pages decode in rtl/bus/axi_peripheral_subsystem.sv. Linux stays off the DMA region: the board device tree sets memory to 0x0fff_c000 bytes.

Who Reaches What¶

CPU cached line port ---------------------------> boot ROM or DDR

CPU uncached AXI ----+
                     +--> main AXI crossbar ----> DMA region or peripherals
PS host AXI --------+

CPU loads to AXI regions wait until they’re at the ROB head, so a device register never gets read speculatively. Cacheable loads stay speculative like normal.

Line Interface¶

A request in rtl/common/soc_pkg.sv has valid, we, a 32-bit address, 16 bytes of write data and 16 byte enables.

  • A transfer happens when valid and ready are both high.

  • Reads return 128 bits with a one-cycle valid pulse and no response ready, so memory holds a response until the path can take it.

  • Line writes have no acknowledgement.

rtl/cpu/cache/dmem_router.sv splits data addresses first. Normal data goes to the D-cache, and the DMA region and devices go to AXI. Instruction fetch always uses the line path.

Routing¶

memory.sv sends each line request to one target:

  1. Boot ROM, below 0x0000_1000.

  2. DDR line bridge, inside the window.

  3. Unmapped responder, everywhere else: reads return zero two cycles later and writes drop.

boot_pending_q, ddr_pending_q and unmapped_pending_q record who owns the next response. The line port assumes one read in flight, because the cache arbiter remembers one owner:

  • A DDR read waits for outstanding ROM and unmapped reads.

  • No read goes while a DDR or unmapped read is out.

  • ROM reads can follow each other, because they return in order.

  • Writes are never held back.

A DDR read issued behind a ROM read would hide its response and deadlock the I-cache.

Uncached DMA Region¶

The AXI crossbar’s memory target covers 0x1fff_c000 to 0x1fff_ffff, and other addresses below 0x8000_0000 decode-error. That lets the CPU and host share buffers without treating all of DDR as uncached.

  1. axi_id_remap narrows five-bit IDs to one bit.

  2. axi_dw_converter widens 32-bit beats to 128 bits.

  3. The address moves from ORCA’s map to the processing system’s.

  4. axi_mux merges this path with the line bridge, and responses return by ID.

Stale Lines¶

ddr_line_bridge buffers one read line. Its invalidate input clears that buffer while the CPU is stopped, because the host rewrites DDR directly, and when a DMA-path write completes. A line already in flight finishes, and the next refill reads DDR again.
