L1 Caches¶

Both L1s are 2-way with 64-byte lines: 32 KiB for instructions and 16 KiB for data. They block on a miss and handle one miss at a time. The RTL is in rtl/cpu/cache/.

Instruction Cache¶

Each way stores one 64-bit word per RAM row, so a lookup reads one fetch group per way with no wide line mux. A lookup takes two cycles: the address goes to the tag and data RAMs, then the tag compare picks the way. A miss refills four 128-bit beats, writing each beat’s low word on arrival and its high word the next cycle, so one RAM port needs no line buffer. The RAMs have no reset, so reset and FENCE.I sweep them one set a cycle.

Why the I-cache response is registered. cpu_l1_subsystem.sv puts a register between the cache and the core. It lines the response up with the predictor’s metadata, and without it the BTB and TAGE verdict would land in the same cycle as the tag compare and the fetch hold decision, which was right on the critical path. Removing it would bring a hit back a cycle sooner.

Data Cache¶

128 sets, write-back. A lookup takes two cycles: accept and drive the RAM index, then compare tags and respond.

Why bank by beat. Each way’s data is four 32-bit banks, one per word of a 128-bit beat. A lookup reads the beat from every bank and picks the word, and a store hit writes one bank with byte enables, so it never reads and merges a line. Lookups use the read port and stores the write port, so a store hit and the next lookup share a cycle. 16 KiB fits in eight small block RAMs that way.

Valid, dirty and replacement bits share a LUT RAM word per set. A pending slot holds one next request, so the cache’s ready comes from a register, not the hit compare, and back-to-back hits run one a cycle. A next request that reads a word being written gets the store’s bytes forwarded.

  • Miss: write back the victim if it’s dirty, then refill four beats and merge a write miss’s bytes in passing.

  • Writeback: streams straight from the banks with no line register, one cycle more than four beats.

  • Replacement: each set stores its next victim, so the miss path computes nothing. With two ways that’s exact LRU in one bit.

L1 Integration¶

cpu_l1_subsystem.sv holds both caches and presents one line port. It keeps a four-entry FIFO of accepted I-cache addresses, since responses carry none. The I-cache’s kill drops the current lookup and every stale response before the replacement PC, which is why fetch needs no epoch filter.

For FENCE.I it runs the D-cache through a write-back-and-invalidate walk of every set and way, then the I-cache through an invalidate walk, and both refuse requests meanwhile. The ROB side is on the commit page.

The line port gives fetch priority, since a stalled fetch blocks the whole front end. It tracks who issued the one outstanding read, and writes need no tracking since they have no response.

Data-Memory Router¶

dmem_router.sv holds one LSU request and sends the DMA region and devices to AXI and everything else to the D-cache. AXI accesses are single-beat 32-bit, and a non-OKAY response becomes a precise fault in the LSU.

The router’s ready only looks at its state and the memory response, so it stays out of a loop through the load queue. The cache hit decides the ready, and the ready decides which load goes next, so every address register is enabled by the handshake and no address waits on the ready.

Limits¶

  • One outstanding line fill; a second miss waits.

  • No prefetcher and no non-blocking misses.

  • Only the uncached AXI path reports errors (traps).

  • Fetch priority can delay a D-cache refill.
