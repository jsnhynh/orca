DDR and main memory¶

This page covers the memory behind the caches: the bridge to the board’s DDR, the uncached path into the same DDR, the simulation model that stands in for it, and the small RAM wrappers the rest of the design builds on.

Related notes: Memory, L1 caches and SoC.

DDR line bridge: rtl/mem/ddr_line_bridge.sv¶

The caches fetch a 64-byte line as four sequential 16-byte beats, one at a time. The bridge starts one AXI burst of four beats when a read misses its line buffer, so the other three beats of that refill are served from the buffer instead of paying the DDR latency again.

  • Window and translation. ORCA address A in the window becomes AXI address PHYS_BASE + (A - WINDOW_BASE). A read outside the window returns zero and a write outside it is dropped. The line port has no error indication, so AXI error responses are not reported.

  • Reads. One read is outstanding. A burst is issued after the request arrives and only once every earlier write has been acknowledged, so a read can never return data older than a write the CPU already issued. The line buffer holds one line; a write to that line invalidates it, and a pending read of it is reissued after the writes drain.

  • Invalidate. An invalidate input also clears the buffered line. memory drives it while the CPU is stopped and whenever a write on the uncached DMA path completes, because those writes reach DDR without passing through the bridge. A burst already in flight finishes first, so the refill that follows never mixes beats of two lines.

  • Writes. Each accepted beat enters a four-entry FIFO and goes out as a single-beat AXI write with its byte strobes (AW and W may be accepted in either order). Up to eight writes may await their B response.

  • AXI rules. valid is held until accepted, ready for R and B is always high, and bursts are 64-byte aligned INCR of four 16-byte beats, so they never cross a 4 KiB boundary. The master ID is one bit and always zero; the shared mux adds the second bit that tells the two sources apart.

ddr_line_bridge_tb checks it against a reference memory behind ddr_axi_mem (random handshakes, latency, and write delay) with sequential line reads, sub-line reads, partial-strobe writes, read-after-write to the same line, out-of-window accesses, and valid-hold protocol assertions. Mutations that let reads overtake writes, skip the buffer invalidation, mistranslate addresses, ignore strobes or forward out-of-window writes each fail it. soc_ddr_tb runs the real SoC and a program (ddr_window_test.s) from DDR that uses every access size, 64 KiB through a 16 KiB cache, and code written into DDR, flushed with fence.i and executed.

The uncached path into DDR¶

The uncached CPU port, FIN’s DMA and the host reach DDR over the 32-bit AXI crossbar. The crossbar’s memory target covers only the 16 KiB DMA region at the top of the window, so any other address below 0x8000_0000 is a decode error. From the target, four steps in memory.sv reach the processing system:

  1. ID remap. axi_id_remap narrows the crossbar’s six-bit IDs to one bit and restores them on the way back. It tracks two IDs at a time, with two transactions per ID.

  2. Width conversion. axi_dw_converter widens the data from 32 to 128 bits. A 32-bit beat keeps its size, and its byte strobes pick the right four lanes of the 16-byte word. A burst of N beats stays N beats. Up to two reads are outstanding.

  3. Address. The ORCA address becomes DDR_PHYS_BASE + (A - DDR_BASE).

  4. Merge. An axi_mux takes this path and the line bridge as its two sources and drives the single M_AXI_DDR master. It adds one ID bit, which routes each response back to its source, and registers the address channels, which costs one cycle on each.

Writes on this path are visible to the CPU’s next line refill once their response returns, which is also when FIN and the host treat them as done. A narrow write to part of a word changes only the strobed bytes. Atomic AXI operations are disabled.

Simulation model: sim/common/ddr_axi_mem.sv¶

Simulation stands in for the processing system with one AXI4 slave, used by every bench. It accepts bursts of any length and size up to the 16-byte bus, echoes IDs so the mux can route responses, and holds a response valid until the master accepts it. Two inputs, stall_pct and max_latency, add random handshake stalls and latency. A read samples the memory as each beat is driven, so a read issued ahead of an earlier write returns the old data; a write lands some cycles after all of its beats arrive.

Two regions are modeled: the bottom of the window, sized by each bench, and the 16 KiB DMA region at the top, so no bench has to allocate the whole 256 MiB. An access outside both stops the simulation. Benches load program images by ORCA address (load_hex) and read memory back (peek32). They start programs the same way the board does: sim/common/host_boot.svh writes the entry address, argument and run ID to the SoC control registers over the host port, and the boot ROM stub jumps to the program.

Clock crossing¶

The CPU line port, memory, and AXI fabric share core_clk; there is no line CDC or response FIFO. FIN’s DMA crosses through the full AXI bridge in fin.sv before it enters this fabric. Its control interface crosses through the AXI-Lite bridge in the opposite direction. See SoC clock domains.

RAM wrappers¶

The smaller arrays in the CPU and FIN use four wrappers under rtl/mem/sram/. All initialize their storage and read output to zero for FPGA power-up and simulation.

rtl/mem/sram/orca_ram_1rw.sv¶

This is a single-clock, single-port RAM. en holds all state when low. When high, we chooses a masked write or a read at the shared address. A write also places the merged new word on rdata, so same-cycle read/write behavior is write-first. MASK_GRAN controls how many adjacent bits each mask bit covers, and STYLE is passed to Vivado’s ram_style attribute. FIN uses this wrapper for storage that is filled and consumed in separate phases. The cache tag arrays use it with MASK_GRAN = 1, and the predictor tables with STYLE = "block".

rtl/mem/sram/orca_ram_1r1w.sv¶

This simple dual-port shape has a dedicated masked write address and a dedicated synchronous read address. re holds the read output when low. A same-address read and write returns the old word because both clocked updates use nonblocking assignments. FIN uses this old-data collision behavior for the accumulator path. The wrapper still has only one writer; it is not a true two-read/write-port RAM.

rtl/mem/sram/orca_sram_1rw_xpm.sv¶

The L1 data banks use this byte-masked, 32-bit wrapper. In synthesis it maps one synchronous write-first port of xpm_memory_tdpram to block RAM with a one-cycle read latency. In simulation it delegates to orca_ram_1rw, so the cache testbench sees the same enabled-read and masked-write contract. Each 64-byte cache block is split across sixteen 32-bit banks per way. A 128-bit backing-memory beat spans four of those banks. All banks are read in parallel, so this organization adds no cache cycle.

None of these attributes is a physical implementation guarantee. Vivado must confirm the inferred primitive, collision mode, port count, and initialization for each instance.

Why the generic and XPM paths remain separate¶

The generic and XPM paths keep the caller-visible masks, arbitration, enabled-output hold and one-cycle storage reads identical across the two targets. Bit-masked predictor storage, byte-masked L1 banks and old-data dual-port arrays are different contracts, so none of them is an alias for another.

Evidence: orca_ram_tb checks the inferred RAM semantics, and the native ROM and SRAM benches exercise the real XPMs.

Limitations: TARGET=xilinx in Verilator is still a generic-storage simulation. It does not run the XPM models and does not prove routed timing. Changing a wrapper needs both the contract tests and an implementation review.
