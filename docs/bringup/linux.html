Linux Bring-Up¶

ORCA boots no-MMU Linux 6.18.7 in machine mode to a BusyBox shell with 256 MiB of RAM, both on the board and in simulation. Linux exercises the core far more broadly than any benchmark: it schedules processes, takes timer interrupts, runs system calls from user mode and uses atomics for its locks.

1. Requirements¶

A Linux kernel needs (1) a trap and privilege model for user programs and system calls, (2) a timer interrupt for scheduling, (3) a console, (4) atomics for locks, and (5) instruction cache maintenance after loading code. A standard RISC-V Linux additionally needs supervisor mode, an MMU with page tables and an SBI firmware layer. The no-MMU port removes those three: the kernel runs directly in machine mode, every process shares one physical address space, and user programs use the FLAT binary format, which is relocated at load time.

FENCE.I

The core already had RV32IMA, machine-mode traps, mret, the timer and FENCE.I. Four additions were needed to close the gap:

  • CLINT page. The kernel’s timer driver expects the SiFive CLINT layout (msip at +0x0, mtimecmp at +0x4000, mtime at +0xBFF8). The timer was extended to also decode a 64 KiB page at 0x8001_0000 that reaches the same registers.

  • time and timeh CSRs. These were added as read-only aliases of mtime, one cycle late; writes trap.

  • UART transmit flags. PULP’s UART reported the transmitter empty before the last character left, so a polling writer overran it. A local fork of the transmitter file reports THRE and TEMT correctly.

  • Minimal U-mode. The kernel runs user code in U-mode and takes system calls as cause 8. MPP with M and U, privilege save and restore on trap and mret, and illegal-instruction checks for machine CSRs in U-mode were added.

Three kernel behaviors were checked in the 6.18 source and made further RTL unnecessary:

  1. A no-MMU kernel is relocatable and takes its RAM base from the device tree, so it runs at 0x1000_0000 without being linked there.

  2. The machine-mode entry code writes the PMP registers under a temporary trap handler. ORCA has no PMP, so those writes trap as illegal CSR accesses and the kernel continues.

  3. With no interrupt controller in the device tree, the 8250 UART driver polls on a timer.

Design Decision: Polled Console vs Interrupt Controller¶

An interrupt-driven console would need a PLIC between the UART and the core. Since the 8250 driver falls back to polling when the device tree lists no interrupt, the PLIC was deferred and the console runs polled. This kept the SoC unchanged apart from the CLINT page.

2. Image and Loading¶

A Buildroot external tree in sw/linux builds the full image with sw/linux/build.sh:

  • Toolchain: Buildroot’s custom RISC-V target set to RV32IMA, ilp32 and uClibc-ng, producing FLAT binaries. One patch was needed so uClibc selects soft float for a RISC-V target without an FPU.

  • Kernel: a minimal config: 32-bit RISC-V, machine mode, no MMU, optimized for size, with only the 8250 driver and console, the CLINT timer, initramfs and FLAT support enabled.

  • Root filesystem: BusyBox in an uncompressed initramfs linked into the kernel image.

  • Device trees: one for simulation and one for the board, differing only in clock and memory size.

The loader places the kernel at the start of ORCA’s DDR window and the device tree at offset 0x03f0_0000. The boot stub passes a single argument in a0, while the kernel expects the hart ID in a0 and the device tree address in a1. A five-instruction shim sits between them:

mv   a1, a0
li   a0, 0
lui  t0, 0x10000
fence.i
jr   t0

The host launches the shim with the device tree address as its argument.

3. Simulation Before the Board¶

The image was first booted in QEMU’s no-MMU virt machine, which separated software problems from RTL problems. It was then booted on the RTL in linux_boot_tb, a Verilator bench with a DDR model preloaded with the kernel and device tree and a UART decoder on the console. The first RTL boot reached the login prompt in 290,296,662 cycles and 93,053,122 instructions, with 1,286 traps.

The bench can run with the retirement oracle and with a DDR model that stalls handshakes and randomizes latency. If nothing retires for 200,000 cycles, it dumps the state of the ROB, load/store queue, LSU, memory router and caches. The missing U-mode was found here, when the first simulated boot failed on /init’s first ECALL.

4. Board Boot¶

On the board, the kernel and device tree are written into PS DDR over the debug port at JTAG speed, so copying the 5 MB kernel takes most of the roughly 23 seconds to the login prompt. The console reaches the host through the Arm console relay. The host sets ORCA’s UART to 115200 baud before starting the relay, watches the console output, and lights one status LED when the kernel starts /init and another at the login prompt. A scripted mode logs in and types one command per prompt, which turns a boot into a repeatable test.

An earlier 200 MHz build reached the shell but finished the scripted session in only 2 of 7 boots. The failures came from the L1 predictor skipping its check of an L0 prediction when a packet’s successor address was still unknown, and the jittery DDR model reproduced the failure in simulation (verification). After the fix, the board completed 8 of 8 boots at 177.8 MHz and 40 of 40 on the shipped 200 MHz build.
