Infrastructure¶

This page describes the hardware and software between the host computer and ORCA during bring-up, and the memory they share.

Host tools¶

  • xsdb. The Vivado debugger runs a Tcl script that sets the boot mode, runs psu_init, loads the bitstream, and then serves read and write requests from the host program. Each access costs one JTAG round trip.

  • Host program. A Python program (orca_host.py) loads payloads, starts and stops ORCA, and prints the console. It works through the host aperture described below.

  • Runner. src/run.py in the repository wraps both tools behind three commands: linux, coremark and act. Only one JTAG session can run at a time, so the host program holds a lock and refuses to start while another session is active, and the Vivado hardware manager must be closed as well.

Host aperture¶

The PS reaches ORCA through a 128 KiB window at 0xA400_0000 in its address map. The first 16 KiB maps to ORCA’s uncached DMA region, the top 16 KiB of its DDR window. A second range maps to the five MMIO pages: FIN (disabled in this build), the UART, the timer, the SoC control registers and the host console. The address map lists the addresses.

Shared memory¶

ORCA’s cached window maps its addresses 0x1000_0000 to 0x1FFF_FFFF onto 256 MiB of PS DDR starting at 0x7000_0000. The memory carries the kernel image, the device tree and the Linux working memory. The window goes through a line bridge and one 128-bit AXI port on the PS side. The two sides are not cache coherent, so the host writes a payload while ORCA is stopped and releases ORCA afterward. The main memory page describes the bridge.

Console¶

ORCA’s UART transmits into a host-side UART endpoint. The relay program on Cortex-A53 core 0 copies those bytes into a receive ring in on-chip memory, and the host reads the ring in bulk over JTAG. Keystrokes go the other way through a transmit ring that the relay forwards into the UART. Polling the UART directly over JTAG limits the console to a low baud rate. The relay allows 115200 baud.

Clocks and reset¶

One PS clock drives ORCA, the host path and the DDR port, at 150 MHz. It comes from the PS real-time PLL (about 1500 MHz) divided by 10, because the default I/O PLL (1000 MHz) can only be divided down to 142.86 or 166.67 MHz near here. The host holds ORCA stopped while it loads memory and releases it by writing the SoC control register. That stop and run lifecycle is described on the SoC page.
